# ALPS Specification

[英語正本](../../ALPS-SPEC.md)

## 1. 適用範囲と規範上の位置付け

ALPSは[プロセスフレームワーク](process-framework.md)を、Agent Skillに記載するプロセス記述の設計とレビューへ適用する。フレームワークはプロセス概念、規範語、境界、参照、変更、評価の規則を定め、本仕様に優先する。

ALPSは、その作業に用いるSkillとして[design-process-description](../../../skills/design-process-description/references/locales/ja/SKILL.md)を一つ提供する。その記述には、それを用いて作成する記述と同じ規則を適用する。ALPSは実行エンジン、スケジューラ、資産管理システム、承認システム、認証制度を提供しない。実行と保存は利用環境の責務である。

## 2. Agent Skillへの対応付け

物理的な`SKILL.md`の形式は[Agent Skills形式](https://agentskills.io/specification)が定める。ALPSは代替形式ではなく、次の対応付けを加える。

| Agent Skillの内容 | プロセスとしての意味 |
| --- | --- |
| frontmatterの`name` | 発見に用いるSkill識別子。 |
| frontmatterの`description` | 作業とSkillの適用場面の要約。 |
| 本文タイトル | プロセス名称。 |
| 本文の目的と成果 | 作業を行う理由と、観察可能な成功条件。 |
| 必要に応じた他の本文内容とリンク先資源 | 必要な詳細、条件、または明確に区別された参照資料。 |

frontmatterは正本の記述と整合しなければならず、その代わりとしてはならない。本文にはフレームワークで定める名称、目的、一つ以上の成果を含めなければならない。ALPSは他の項目やセクションを一律には要求しない。通常のAgent Skillメタデータがプロセス要件を追加することはない。

プロセス記述を記載する各Skillは、そのプロセスについて一つの識別可能な正本記述を持たなければならない。本配布では、ルートの`skills/design-process-description/SKILL.md`が、そのプロセスの英語正本である。日本語対応ファイルは翻訳である。発見用の文言、Host表示、テンプレート、例は、対象とする出典の正本の位置付けと範囲を維持しなければならない。

Skillの読込みや要約の閲覧は、作業が実行されたことを示さない。プロセスを整理したりビューを示したりする参照資料は、プロセス記述と区別できなければならず、ALPS独自の型宣言を必要としない。

## 3. 資源と配布

Skillは、必要な各付属資源の役割と利用条件を識別しなければならない。必要な参照は、通常のリンクまたは識別情報によって配布パッケージから利用できなければならない。必須参照を確認できない場合は影響する作業とともに報告しなければならず、別版や同名資料で代用してはならない。

ALPS Pluginは、`skills/`、共有の`spec/`正本と日本語訳、適用されるHostのmanifestと表示資源を含む。Skillから仕様への相対リンクは、このPluginルートの配置に依存する。Skillディレクトリだけの配布では、必要な正本を提供できない。`.agents/skills/`の開発用SkillはPluginのSkillではない。

Host別manifestはそれぞれのHostの形式を維持する。内容の所在や表示を定めるものであり、プロセスの意味を再定義してはならない。リポジトリ整合性検証は、配布境界、パス、資源、翻訳、版の整合性を評価するものであり、意味の正しさを判定するものではない。

## 4. 設計とレビューの資源

[最小テンプレート](../../../skills/design-process-description/references/locales/ja/SKILL-template.md)は、通常のfrontmatterと名称、目的、成果から始める。[具体例](../../../skills/design-process-description/references/locales/ja/examples.md)は、詳細を追加する場面と、不確実な事例や未成功の事例のレビューを示す。いずれも参考情報であり、一律の要件を加えてはならない。

プロセス記述のレビューでは、対象の作業と範囲に対してフレームワークを適用しなければならない。Agent Skillの形式のレビューでは、適用形式、発見情報の整合性、必要な資源、正本の位置付けを別に確認しなければならない。一つのレビューでの良好な結果を、別のレビュー、実行証拠、外部要求の充足の代わりとしてはならない。
