# ALPS — エージェントスキル向けプロセスプロファイル

> 本書は日本語版である。正本となる英語版は[ALPS-SPEC.md](../../ALPS-SPEC.md)であり、内容が矛盾する場合は英語版を優先する。

ALPSは、[プロセスフレームワーク](process-framework.md)（PF）をエージェント
スキルへ適用する。再利用可能なプロセス知識を、エージェントスキルの可搬な
発見面および記述面へ表現するための薄いプロファイルである。

## 1. 適用範囲

本規格は、プロセスをエージェントスキルとして表現し、そのプロセスを発見用に
投影し、任意の詳細および付随資源を含め、組合せ時の受け渡しを記述し、検証結果を
解釈する場合に固有の要求事項を定める。

本規格は、一般的なプロセス意味論、ホストによる発見または振分け、スキルの選択
または有効化、表現対象プロセスの実行、採用、配布方針、版管理、廃止、組織的な
統治または一般的なライフサイクルエンジンを定義しない。

## 2. 規範上の正本および優先関係

プロセス、プロセス記述、プロセスインスタンス、名称、目的、成果、活動、タスク、
入力、出力、統制事項、制約、実行支援要素、開始基準、完了基準、受け渡し、
テーラリング、アセスメント、プロセスモデル、プロセス参照モデル、プロセスビュー
およびその他すべての一般的なプロセス構成概念は、PFを正本とする。

本規格とPFが競合する場合は、PFを優先する必要がある。ALPSは、PFの要求を弱め、
PFが禁止する行為を許可し、またはPF構成概念を再定義してはならない。

エージェントスキルの物理形式は、
[Agent Skills specification](https://agentskills.io/specification)によって定まる。
ALPSは、その形式を再記述しない。

規範語とその意味はPFの定めによる。本規格はそれらを継承し、再定義しない。

## 3. プロセススキル表現

既定では、一つのエージェントスキルが一つのプロセスを表現する。ALPSは、他の
PF構成概念に対する追加の型付き表現種別を定めない。

一つのスキルパッケージは、識別可能な正本プロセス記述を一つだけ含む必要がある。
正本プロセス記述は、PFが要求するプロセス名称、目的および成果を含む必要がある。
そこに含める各任意プロセス要素は、PFに従う必要がある。

スキルの`name`は発見用識別子である。プロセス名称は表現対象となる作業のPF上の
識別情報であり、正本プロセス記述の見出しとして提示する必要がある。プロジェクト、
製品またはパッケージのブランド名は、そのブランド自体が表現対象となる作業の
中心的な関心である場合を除き、プロセス名称の代わりに用いてはならない。

配布対象の[再利用可能な作業設計プロセス](../../../skills/reusable-work-design/references/locales/ja/SKILL.md)は、
本プロファイルの主要例である。スキル識別子は`reusable-work-design`、プロセス名称は
`再利用可能な作業設計プロセス`であり、プラグインのブランド名は引き続き`alps`である。

## 4. 発見用投影

スキルの`name`および発見用`description`は、ホストによる発見のために、表現対象
プロセスを投影したものである。これらを正本プロセス記述の代わりにしてはならない。

発見用`description`は、プロセス名称、目的、成果、プロセス境界および適用条件と
整合する必要がある。スキルを適用しない重大な条件を含め、適用可能性の判断に
必要な情報を示すのが望ましい。

表現についての文言上の主張を含むという理由だけで、発見用投影を保証証拠として
扱ってはならない。

## 5. 任意の詳細およびスキルパッケージ資源

任意のプロセス詳細は、意図する発見、適用、組合せおよびアセスメントのニーズに
見合って含める必要がある。それらのニーズを実質的に支援しない詳細は省略し、
または参考情報として明確に区別するのが望ましい。

付随資源は、理解または適用を支援してよい。その役割および利用条件を識別でき、
必須参照が解決し、正本プロセス記述と競合せず、別の正本プロセス記述を生じさせない
必要がある。

物理的なディレクトリ、ファイル、メタデータおよび読込み動作には、Agent Skills
specificationおよび適用するホストの規則を適用する。これらはプロセス意味論を
変更しない。

## 6. 組合せ時の受け渡し

プロセスの組合せを記述する場合は、提供側プロセスの出力から受領側プロセスの
入力へのすべての対応を明示する必要がある。受け渡しを理解しアセスメントできる
ように、その方向および交換項目を識別できる必要がある。

この受け渡し要求によって、ALPSがスキルの振分け機構、リゾルバまたは実行エンジンに
なるわけではない。

## 7. 検証およびアセスメントの境界

形式検査、ロード、構文解析、スキルの有効化、テンプレートの完成または文言上の
自己主張だけで、意味上の適合、成果達成または実行適合を成立させてはならない。

プロセススキル表現のアセスメントと、表現対象プロセスの実行に関するアセスメントは
別である。適合主張は、その対象、基準、範囲および証拠を識別する必要がある。
一般的なアセスメントおよび適合の意味はPFによって定まり、ALPSは独自の適合分類を
追加しない。
