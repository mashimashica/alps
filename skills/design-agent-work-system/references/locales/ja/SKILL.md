# エージェント作業システムの設計

## 目的

対象の仕事と適用条件に適した、エージェント・ツール・情報資源・実行環境の構成と相互作用を設計し、その実現可能性と有効性を確かめる。

## 成果

- 構成の責務と相互作用が、適用条件の下で対象の仕事を網羅している。
- 判断と処理の配分が、仕事と利用可能な能力によって正当化されている。
- インターフェースと情報供給が、必要な相互作用と結果の解釈に十分である。
- 依頼範囲内の実現が、適用可能な証拠に裏付けられ、定められた動作を満たしている。
- 実現可能性と有効性の判断が、検討した仕事に裏付けられ、仮定、未確認事項、限界が明示されている。

## 活動とタスク

以下のタスクは、推奨と明示したものを除き、依頼範囲内で必須とする。それらの関係は、証拠の変化に応じた設計の再検討を可能にする。

### 設計の基礎の確認

1. 対象の仕事の参照元となる記述、適用条件、利用可能な能力、依頼された設計・実装・評価の範囲を識別する。影響を受ける関係者からの必要な情報を確認し、依存する判断を制限する不足を識別する。
2. 仕事の記述が、依頼された設計に十分であるかを判断する。その意味と成功条件は二重に保持せず、参照する。設計から前提の問題が見つかった場合は、影響する記述を再検討する。変更が依頼範囲に含まれ、正当化される場合を除き、その意味を維持する。

### 責務と相互作用の構成

1. 必要な能力に照らして、既存のエージェント・ツール・資源・環境を評価する。必要な文脈依存の解釈・選択・構成をエージェントへ、確定した処理と判断規則を適切な実装へ配分する。
2. 構成要素の責務とインターフェース、情報の出所と条件、結果と失敗への対応を定める。内部モジュールの境界と、エージェントへ公開する操作を区別する。有用な場合は安定した操作をまとめ、意味のある選択を維持する。
3. ツールに実装する規則や制限を、適用される統制事項と制約へ、参照元と範囲を識別できる形で対応付ける。ツールや環境の限界が、仕事の実現可能性や結果へ与える影響を評価する。

    > NOTE 一つの操作が、処理能力の供給、判断基準の適用、制限の強制を担うことがある。これらの役割は、仕事に対する異なる関係を表す。[能力・基準・制限の例](examples.md#能力基準制限)は、測定ツールにおける対応関係を示している。

4. 方法・ツール・接続の新設や調整が必要な不足を識別する。境界は、凝集性、変更影響、利用・組合せ・検証のしやすさで判断する。

### 依頼された構成の実現

1. 依頼範囲内で、適用される環境を用いて必要な能力を実装・接続する。ツールの利用方法、依存関係、結果の解釈、失敗への対応、状態を変更する影響を、必要な箇所で確認できるようにする。
2. 対象がSkillである場合、仕様のセクション、リスト、NOTEの規則を用いて、必要なツール利用と条件を`SKILL.md`と必要な資源へ反映する。同梱する業務処理は対象Skillの`scripts/`に置く。設計や評価のツールは、それらが支援する設計の仕事に対応させる。
3. 依存する操作の前に、必要条件を確認する。状態を変更する操作を再試行する前に、不確かな影響や一部だけ生じた影響へ対応する。

### システムの評価と調整

1. 対象の仕事に照らして、設計の責務、関係、条件をレビューする。関係する失敗や不完全な結果を含め、構成要素と接続を定められた動作に照らして検証する。

    > NOTE この設計の仕事では、仕様と適用される仕事の要求が基準となる。既存のコマンドツールが、構成要素の検査や接続の試行を支える。その観測は設計を評価する証拠となり、システム全体の有効性には、代表的な仕事におけるエージェントの解釈と対応も関わる。

2. 許可され、利用可能な範囲で、意図したエージェント・ツール・情報・環境を用いた代表的な仕事を評価する。証拠と適用条件に照らして仕事の成果を評価し、ツールの完了や生成された出力と区別する。
3. 証拠や能力変化が根拠となる場合、指示、情報供給、公開操作、配分を再検討する。能力の限界を補う誘導を見直す際も、仕事固有の知識と条件を維持する。影響する動作を再検証する。
4. 各判断の対象、基準、証拠、範囲、未実施の検証、未解決の指摘を報告する。レビューでは、提供された設計について本Skillの成果を評価する。欠陥を識別しても、未達成のままの条件が満たされたことにはならない。

## 統制事項

このプロセス記述には[プロセスフレームワーク](../../../../../spec/locales/ja/process-framework.md)を、設計対象には[エージェント作業システムの設計原則](../../../../../spec/locales/ja/agent-work-system-design.md)を、Skillにおける両者の統合には[ALPS Specification](../../../../../spec/locales/ja/ALPS-SPEC.md)を適用する。これらは必須参照である。設計範囲は、対象の仕事の記述、ユーザーの依頼、利用環境の適用条件が定める。

## 制約

レビューだけの依頼には、指摘と依頼された修正を返し、求められていない変更を行ってはならない。対象業務の実行は別の適用であり、適用される権限の範囲内に収めなければならない。参照不足や未確認の条件は、依存する行為と判断を制限しなければならない。独立した分析や草案作成は、それぞれの条件の範囲内で続けてよい。実施していない評価は、未確認のまま明示しなければならない。
