# ALPS準拠の`SKILL.md`向け代表プロセステンプレート

この資料は、読みやすいプロセス記述を起草するための参考例である。プレースホルダーをプレーンテキストに置き換えた後の具体的なMarkdown・フロントマター形式は、[`alps-markdown/v2`](../../../../../spec/alps-markdown-v2.md)という環境への対応付けと互換性を持つ。この互換性は、当該の物理形式、見出しまたは並び順をALPSの要求事項にするものではない。本テンプレートは、発見層と実行層の物理的な分離を要求しない。プロセスフレームワーク、ALPSおよび適用される実行環境の規則を優先する。

## 利用上の注意

- 本例はプロセス記述に用いる。プロセスモデル、プロセス参照モデルまたはプロセスビューを表現する場合は、表現種別に応じたALPS要求事項および環境への対応付けのプロファイルを適用する。
- 名称、目的および成果は必須要素として保持する。他の節は、目的と必要な詳細度に応じて含めるのが望ましい。
- 目的の最初の文と、その後に置く参考説明とを区別する。参考説明で目的を追加または変更しない。
- 成果は出力の作成ではなく、結果が成立している状態として記述する。
- タスクは、一つ以上の成果の達成を支援する個別の行為を表すことを主たる機能とし、その行為の対象と操作が判別できるように記述する。
- 制約、判定基準または品質条件をタスクに含める場合、それらを行為の対象または行為を方向付ける条件として扱い、タスクの主たる機能を個別の行為として維持する。
- 主たる機能が個別の行為ではない記述は、その機能に対応する別の要素に置く。
- タスクごとに、要求事項、禁止事項、推奨事項、許容される行為または通常実施される行為のいずれかを規範語で判別可能にする。すべての種類を含める必要はない。
- エージェント、ツールまたは実行環境は入力に含めず、実行支援要素として扱う。
- 必須の参照先は、対象環境で解決可能である必要がある。パッケージには、表現対象のプロセスの理解・適用または出力の作成を直接支援する付随資源だけを含めるのが望ましい。
- 意思決定ゲートはスキル記述の構成要素にせず、表現対象のプロセスの適用を制御する別個の意思決定機構として扱う。
