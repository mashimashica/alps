# `SKILL.md`向け最小プロセステンプレート

この参考用起草支援資料は、プロセス記述に必要な意味上の中核から始める。そのMarkdown形式および順序はALPS要求事項ではない。[プロセスフレームワーク](../../../../../spec/process-framework.md)、[ALPS仕様](../../../../../spec/ALPS-SPEC.md)、ならびに適用するAgent Skillおよび実行環境の規則に従う。

## 最小テンプレート

```markdown
---
name: <lowercase-hyphen-name>
description: <プロセスが行うこと、本スキルを使用する状況、および適用可能性の判定に必要な情報を記述する。>
---

# <短い名詞句のプロセス名称>

## 目的

<本プロセスを実行する上位目的を記述する。>

## 成果

- a) <肯定的で観測可能かつ評価可能な一つの結果状態が成立している。>
- b) <目的に必要な一つの独立した結果が成立している。>
```

## 必要な場合だけ追加する

| 任意の詳細 | 追加する条件 |
| --- | --- |
| 入力、出力、開始基準および完了基準 | 呼び出しまたは受け渡しに、明示的な境界条件または受け渡す項目が必要な場合。 |
| 活動およびタスク | 作業内容の標準化が必要な場合、またはタスク適合の基準として用いる場合。 |
| 統制事項、制約および実行支援要素 | 上位の情報源から継承されない、プロセス固有の方向付け、制限または能力依存がある場合。 |
| インターフェースおよび追跡可能性 | モデル、ビュー、組合せまたは品質リスクに、対応関係、来歴、変更伝播または証拠関係が必要な場合。 |
| 証拠および記録 | リスク、意思決定ゲート、受け渡し、テーラリング、監査または明示的な適合主張によって、永続的な証拠が正当化される場合。 |

`適合`節は既定で追加しない。実際の主張を行う場合だけ追加し、新しい物理形式を定義せず、対象、適用する基準版、範囲、基準、結論、証拠および制限を識別する。

## 起草時の確認

- 任意要素ごとに、それを削除すると成果評価、境界、受け渡し、重要な判断または主張証拠が失われるかを確認する。失われない場合は省略する。
- 各成果およびタスクは一つの意味にする。タスクでは、一つの判別可能な行為およびその規範属性を示す。
- エージェント、ツールおよび実行環境が実行能力を提供する場合は、入力ではなく実行支援要素として扱う。
