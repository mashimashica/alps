# 再利用可能な作業設計プロセス

## 目的

このプロセスは、反復または共有されるエージェント作業を、再利用可能かつ
評価可能なプロセススキルとして確立する。

プロセススキル表現の作成および改訂は、本プロセスの境界内にある。
表現対象となるプロセスの実行および採用済みスキルの統治は、その境界外にある。

## 成果

- a) 作業を再利用するニーズおよびその想定利用文脈が識別されている。
- b) 表現対象となる作業が、一つの整合したプロセス境界を持っている。
- c) プロセス名称、目的および成果が、一つの内部整合した意味上の中核を形成している。
- d) 各成果が、目的に関係する、肯定的で観測可能かつ評価可能な結果状態を
  一つ示している。
- e) プロセス記述の詳細度が、意図する発見、適用、組合せおよびアセスメントの
  ニーズに見合っている。
- f) 必要な参照および受け渡しが明示され、利用可能である。
- g) 得られたプロセススキルを、明示されていない実行主体、ツール、方法、測定量
  または実行順序に依存せず適用できる。
- h) 重大な欠陥、前提、制限事項および未解決事項が明示されている。

## 活動とタスク

活動、タスクおよびその記載順は記述を整理するためのものであり、実行順序を
規定しない。

### ニーズおよび境界の設計

1. 反復または共有される作業およびその想定利用文脈を識別する必要がある。
2. 新しいスキルを作成する前に、既存スキルに適切な対象範囲があるかを調べるのが
   望ましい。
3. 関連する作業の周囲に、一つの整合したプロセス境界を確立する必要がある。
4. 独立した目的は、互いに別のプロセスへ分離する必要がある。
5. プロセス名称は、中心的な関心を表し、目的を要約しない簡潔な名詞句として
   記述する必要がある。
6. 英語のプロセス名称は、“Process”という語で終えるのが望ましい。
7. プロジェクト、製品またはパッケージのブランド名は、そのブランド自体が
   表現対象となる作業の中心的な関心である場合を除き、プロセス名称の代わりに
   用いてはならない。

### 意味上の中核の設計

1. 目的は、プロセスを実行するための上位目的を、簡潔な文で示す必要がある。
2. 目的は、期待される成果を包含する必要があり、活動または成果を要約しては
   ならない。
3. 各成果は、肯定的で観測可能かつ評価可能な結果状態を一つ示すように記述する
   必要がある。
4. 成果物、文書、記録または情報項目を生産することが主たる意味である場合、
   それを成果ではなく出力として分類する必要がある。
5. 成果の集合が目的に対して十分であることを確認する必要がある。
6. 各成果が目的に関係することを確認する必要がある。
7. 名称、目的および成果の内部整合性を確認する必要がある。

### 必要な詳細の選択

1. 各任意プロセス要素の必要性を、意図する発見、適用、組合せおよび
   アセスメントの文脈に照らして評価する必要がある。
2. 活動およびタスクがないことで適用の信頼性または一貫性が実質的に低下する
   場合は、それらを追加するのが望ましい。
3. 変換または受け渡しの境界を理解する必要がある場合は、入力および出力を
   追加するのが望ましい。
4. 追加しなければ呼び出しまたは完了が曖昧になる場合は、開始基準および
   完了基準を追加するのが望ましい。
5. 許容される実行を実質的に方向付け、または制限する場合は、統制事項および
   制約を追加する必要がある。
6. プロセスを実行するエージェント、人、モデル、ツールおよび実行環境は、
   入力ではなく実行支援要素として分類する必要がある。
7. 実行順序は、実際の時間的制約が要求する場合に限り記述する必要がある。
8. プロセスの組合せを対象とする場合は、提供側出力から受領側入力へのすべての
   対応を明示する必要がある。

### 検証および削減

1. 各記述を除去した場合に、正しい発見、適用、組合せまたはアセスメントが
   実質的に損なわれるかを判定して、各記述を検証する必要がある。
2. その検証を通過しない記述は、削除するか、参考情報へ移す必要がある。
3. スキルの発見記述が、プロセス名称、目的、成果、境界および適用条件と
   整合することを確認する必要がある。
4. 必須参照を解決する必要がある。
5. 不確実性または品質リスクによって成果達成可能性が不明確な場合は、
   代表的試行を実施するのが望ましい。
6. 検出した欠陥、前提、制限事項および未解決事項を記録する必要がある。
7. 品質リスクに応じて、作成者から独立した観点を得るのが望ましい。

## 入力

代表的な入力には、次を含む。

- 反復または共有されるエージェント作業
- レビューまたは改訂を要する既存プロセススキル
- 想定利用者および利用文脈
- 適用する統制事項および制約
- 改訂に関係する実行証拠または教訓

## 出力

代表的な出力には、次を含む。

- 一つの正本となるプロセススキル表現
- 後続の判断に必要な場合の検証所見

## 開始基準

- 反復または共有される作業のニーズ、あるいは既存プロセススキルのレビュー
  または改訂の依頼が識別されている。
- プロセス境界を確立するために十分な範囲で、想定利用文脈を識別できる。

## 完了基準

- 宣言した各成果の達成状況が評価されている。
- 正本となるプロセススキル表現を利用できる。
- 必須参照が解決している。
- 重大な欠陥、前提、制限事項および未解決事項が明示されている。
- 表現を、別に行う採用判断へ引き渡すことができる。

## 統制事項

- [プロセスフレームワーク](../../../../../spec/process-framework.md)がプロセスの
  意味を統制する。
- [Agent Skills specification](https://agentskills.io/specification)がスキルの
  物理形式を統制する。
- 適用するシステム、ユーザー、リポジトリ、安全、プライバシーおよび法的指示が、
  それぞれの宣言範囲内で作業を統制する。

## 制約

- 一回限りの作業は、具体的な再利用、共有、組合せ、レビューまたは
  アセスメントのニーズがある場合を除き、プロセススキルへ変換してはならない。
- 一般プロセス記述は、特定の実行主体、方法、ツール、測定量、管理方法または
  実行順序を規定してはならない。
- 本プロセスは、記述対象となるプロセスを実行し、または採用済みスキル資産を
  統治する範囲まで拡張してはならない。
- 本プロセスの完了を、得られた表現の適合を独立して証明するものとして扱っては
  ならない。
