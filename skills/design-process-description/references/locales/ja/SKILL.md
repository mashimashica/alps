# プロセス記述の設計

## 目的

対象作業の目的と成功条件を、必要十分な境界と詳細を持つ、理解・適用・評価可能なプロセス記述として明確にする。

## 成果

- 対象作業が、目的、適用範囲、隣接作業との境界によって識別されている。
- 成功条件が、目的に関連し、全体として目的を満たすために十分な、観察可能な結果状態として記述されている。
- 作業の理解・適用・評価に必要な詳細が記述に含まれている。
- 適用条件によって必要となる場合を除き、実行手段の選択が開かれている。
- フレームワークおよび必要な参照との、記述の整合性が明らかになっている。
- 未確認事項と適用上の限界が明示されている。

## 活動

以下のタスクは、推奨と明示したものを除き、依頼された範囲内で必須とする。それらの関係は、理解の進展に応じて記述を再検討することを支える。

### 対象作業の明確化

- 依頼範囲と、利用可能な記述または対象作業の情報を識別する。
- その情報から、作業の目的と隣接作業との境界を明確にする。
- 意図した範囲や成功条件を変え得る不確実性を識別する。

### 成功条件と作業の記述

- 目的に関連し、全体として目的を満たすために十分な、観察可能な成果を記述する。独立して評価できる結果を区別可能に保つ。
- 作業の理解・適用・評価に必要な詳細を定める。作業詳細が必要な場合は、関連する行為を有用な粒度の活動とタスクへ整理し、成果への寄与を確認する。
- 必要な入力、出力、統制事項、制約、実行支援要素、開始基準、完了基準を、その機能に基づいて記述する。必須の方法と依存関係は適用範囲とともに維持し、それ以外の実行上の選択を開いておく。

### 正本と関係の整合

- 正本の記述を識別し、必要な参照を意図した出典に照らして確認する。
- 関連する作業と共有する情報の意味、利用、変更影響を、どの作業が参照・更新するかを含めて明確にする。
- 変更では、対象の正本と要素、範囲、根拠、影響、必要な再検証を明確にする。正本の変更、文脈限定の変更、一回の適用に固有の選択、見せ方の変更を区別する。

### 記述の評価

- 要素の整合性と成果の網羅範囲を含め、フレームワークと適用される文脈上の要求に照らして記述を評価する。
- 曖昧さ、裏付けのない成功条件、適用上の限界を明らかにできる場合は、代表的な事例を検討することが望ましい。
- 残る欠陥と未確認事項を含む指摘を、その証拠と影響範囲とともに報告する。レビューでは、提供された記述について本Skillの成果を評価する。欠陥を識別しても、未達成のままの条件が満たされたことにはならない。

## 統制事項

意味には[プロセスフレームワーク](../../../../../spec/locales/ja/process-framework.md)を、Agent Skillとしての表現には[ALPS Specification](../../../../../spec/locales/ja/ALPS-SPEC.md)を適用する。これらは必須参照であり、フレームワークが優先する。変更の範囲は、ユーザーの依頼と利用環境の適用条件が定める。

## 制約

レビューだけの依頼には、指摘と依頼された修正を返し、求められていない全面改訂を行ってはならない。対象の作業の実行や外部状態の変更には、適用される権限が必要である。未確認の参照や条件は、それに依存する判断や行為を制限しなければならない。独立した作業は、それぞれの適用条件の範囲で続けてよい。
