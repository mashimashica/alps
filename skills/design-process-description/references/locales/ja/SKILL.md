# プロセス記述の設計

## 目的

対象作業の目的と成功条件を、必要十分な境界と詳細を持つ、理解・適用・評価可能なプロセス記述として明確にする。

## 成果

- 対象作業が、目的、適用範囲、隣接作業との境界によって識別されている。
- 成功条件が、それぞれ目的の達成に必要で、全体として目的を満たすために十分な、観察可能な結果状態として記述されている。
- 作業の理解・適用・評価に必要な詳細が記述に含まれている。
- 適用条件によって必要となる場合を除き、実行手段の選択が開かれている。
- フレームワークおよび必要な参照との、記述の整合性が明らかになっている。
- 未確認事項と適用上の限界が明示されている。

## 活動とタスク

以下のタスクは、推奨と明示したものを除き、依頼された範囲内で必須とする。それらの関係は、理解の進展に応じて記述を再検討することを支える。

### 対象作業の明確化

1. 依頼範囲と、利用可能な記述または対象作業の情報を識別する。
2. 影響を受ける関係者からの必要な情報を用いて、作業の目的と隣接作業との境界を明確にする。その情報の出所と適用可能性を確認し、不足を識別する。
3. 意図した範囲や成功条件を変え得る不確実性を識別する。

### 成功条件と作業の記述

1. それぞれ目的の達成に必要で、全体として目的を満たすために十分な、観察可能な成果を記述する。独立して評価できる結果を区別可能に保つ。
2. 作業の理解・適用・評価に必要な詳細を定める。作業詳細が必要な場合は、関連する行為を有用な粒度の活動とタスクへ整理し、成果への寄与を確認する。

    > 注記 活動は関連する仕事をまとめ、タスクは個々の行為を述べる。[本番リリースの例](examples.md#本番リリース)は、この構造と、対象の仕事に付ける説明の注記を示している。

3. 必要な入力、出力、統制事項、制約、実行支援要素、開始基準、完了基準を、その機能に基づいて記述する。必須の方法と依存関係は適用範囲とともに維持し、それ以外の実行上の選択を開いておく。
4. Markdownではフレームワークの記述規則を適用する。対象がAgent Skillの場合は、本文にプロセス記述を、frontmatterに発見用の識別子と、作業およびその適用場面の要約を記述する。frontmatterとHost表示を、記述の意味と範囲に整合させる。

### 参照元と関係の整合

1. 参照元となる記述を識別し、必要な参照を意図した出典に照らして確認する。必要な資源の役割と利用条件を明確にし、参照資料と作業の記述を区別する。Skillでは、意図した配布構成の下でパッケージ内のリンクが解決し、外部参照が参照元とアクセス条件を識別していることを確認する。
2. 関連する作業と共有する情報の意味、利用、変更影響を、どの作業が参照・更新するかを含めて明確にする。
3. 変更では、対象となる記述と要素、範囲、根拠、影響、必要な再検証を明確にする。参照元となる記述の変更、文脈限定の変更、一回の適用に固有の選択、見せ方の変更を区別する。
4. プロセスを選択する場合やその意味を変更する場合は、判断の裏付けに必要な証拠を用いて、提案された選択肢を目的と適用条件に照らして評価する。

### 記述の評価

1. 要素の整合性と成果の網羅範囲を含め、フレームワークと適用される文脈上の要求に照らして記述を評価する。基準と証拠が、レビュー対象の記述と文脈に適用できることを確認する。根拠となる情報や条件が変わった場合は、影響する判断を再評価する。

    > 注記 この設計の仕事では、フレームワークと適用される要求が統制事項となる。読取り、検索、形式検査の能力は実行支援要素であり、形式検査の結果は検査した側面についての証拠となる。整合性と成果の十分性には、仕事とその条件の解釈も関わる。

2. 曖昧さ、裏付けのない成功条件、適用上の限界を明らかにできる場合は、代表的な事例を検討することが望ましい。
3. 指摘を、依頼範囲内でのさらなる改訂やレビューに役立てることが望ましい。
4. 残る欠陥と未確認事項を含む指摘を、その証拠と影響範囲とともに報告する。レビューでは、提供された記述について本Skillの成果を評価する。欠陥を識別しても、未達成のままの条件が満たされたことにはならない。

## 統制事項

意味とMarkdownの記述様式には[プロセスフレームワーク](process-framework.md)を適用する。対象がAgent Skillの場合、物理的な形式には[Agent Skills仕様](https://agentskills.io/specification)を適用する。これらは、それぞれの対象について必須参照である。変更の範囲は、ユーザーの依頼と利用環境の適用条件が定める。

## 制約

レビューだけの依頼には、指摘と依頼された修正を返し、求められていない全面改訂を行ってはならない。対象の作業の実行や外部状態の変更には、適用される権限が必要である。未確認の参照や条件は、それに依存する判断や行為を制限しなければならない。独立した作業は、それぞれの適用条件の範囲で続けてよい。
