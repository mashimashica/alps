# 境界と詳細

この参考資料は、**何を再利用可能なプロセスに含め、どの詳細を一回の適用側へ残すか**に答えるために使用する。

## プロセスと一回の適用

プロセス記述は、反復適用を通じて有用であり続ける知識を保持する。一回の適用では、具体的な対象、要求結果、値、人、ツール、ファイル、リポジトリ状態、日付その他の局所的な文脈を与える。

変更すると反復作業そのものが変わる情報だけをプロセス記述に置く。一つの妥当な適用を選ぶ情報は適用側に残す。

| 再利用可能なプロセス知識 | 適用固有の情報 |
| --- | --- |
| 観察できなければならない成功の種類 | この案件で要求される対象または受入値 |
| 関連するすべての利用で必要な安全確認 | 現在の証拠とリスク水準 |
| 必須の受け渡しが持つ意味 | 今回使う実際のファイル、メッセージまたは受領者 |
| 作業を開始できるかを決める条件 | その条件が現在成立しているか |

## 境界を定める

一つの目的とその成果の達成に必要な作業を含める。上流の準備、下流での利用、統制および隣接目的は、プロセス自身がその成功条件を確立する必要がない限り除外する。

次の観点で確認する。

- **凝集性:** 含まれるすべての要素が同じ目的へ寄与する。
- **完全性:** 選んだ境界内の反復作業を暗黙の依存として残さない。
- **再利用性:** 代表事例を通して記述を適用できる。
- **成功の範囲:** プロセスが合理的に確立または評価できる状態だけを主張する。

## 粒度を選ぶ

独立した目的を個別に選択、実行、変更または評価できる場合は記述を分割する。目的が一つの成功条件の断片に過ぎず、分離によって永続的な暗黙文脈や意味のない受け渡しが必要になる場合は統合する。

複数のタスクがあるという理由だけで分割しない。頻繁に一緒に使うという理由だけで統合しない。

## 必要な場合だけ活動とタスクを追加する

名称、目的および成果から始める。次のいずれかが成立する場合だけ活動またはタスクを追加する。

- 作業内容が重大な点で曖昧になる。
- 省略により正確性または安全性のリスクが生じる。
- 成果だけでは必須の責任または受け渡しを理解できない。
- 評価のために本質的な作業の安定した記述が必要である。

推奨する実装手順ではなく、必要な作業内容を記述する。まれな事例のための網羅的チェックリストは避ける。

## 不要な実装固定を避ける

特定の固定がプロセスの意味または安全性に必要でない限り、再利用可能なプロセスを実行者、役割、エージェント、ツール、方法、指標、ファイル形式、リポジトリ配置および実行順序から独立させる。

固定が必要に見える場合は、次を確認する。

1. 別の有能な実行者やツールではプロセスが無効になるか。
2. その順序は実際の依存関係か、単に便利な作業方法か。
3. 指標は成果や制約を定義するか、単一実装を報告するだけか。
4. プロセスを変えずに適用側で詳細を与えられるか。

全順序の固定より依存関係と条件を優先し、妥当な代替方法を残す。

## 開始基準と完了基準

検査可能な条件が成立する前に作業を始めてはならない、または作業が意味を持たない場合だけ開始基準を追加する。成果だけでは完了可能な時点が明確にならない場合だけ完了基準を追加する。

すべての入力を開始基準として、またはすべての成果を完了基準として繰り返さない。実際の開始または完了の曖昧さを解消する基準にする。

## 既存スキルを簡素化する

失敗した結果、繰り返される確認、無視される指示、重複した説明、過大な読込量、壊れやすい分岐および回避策など、実際の利用証拠を用いる。

各詳細について、削除すると代表事例で正確性、安全性、意味、組合せ可能性または評価可能性が下がるかを確認する。下がらなければ削除する。規則が繰り返し例外を必要とする場合は、背後の条件へ置き換えるか削除する。複数箇所が同じ判断を行う場合は、一つの正本だけを残す。

廃止した内部構造との互換性だけを理由に複雑性を残さない。推測的な拡張点を作らず、未解決の不確実性を記録する。

## 結果

反復適用に必要な最小の持続的詳細を備えた、一つの凝集した境界を作る。未解決の境界判断と、それを解決するために必要な証拠を示す。
