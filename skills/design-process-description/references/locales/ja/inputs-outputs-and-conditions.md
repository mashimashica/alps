# 入力、出力および条件

この参考資料は、**プロセスの周囲にある各項目や条件がどの機能を果たすか**に答えるために使用する。

これらの区別は、プロセス、条件または受け渡しを明確にする場合だけ追加する。空の分類を作らない。

## 機能上の区別

| 種類 | 機能 | 判断の問い |
| --- | --- | --- |
| 入力 | プロセスが消費または変換する情報、物質または状態 | 何が作業へ入り、結果の生成に使われるか。 |
| 出力 | プロセスが生み出す情報、物質または状態 | 作業の結果として何がプロセスから出るか。 |
| 統制事項 | 判断または許容可能な作業を方向付ける規則や指示 | 選択方法または結果の受入れを何が方向付けるか。 |
| 制約 | プロセスが超過または違反してはならない限界 | 選択肢を何が制限するか。 |
| 実行支援要素 | 実行を可能にする資源または能力 | 作業対象として変換されず、実行を何が支援するか。 |
| 開始基準 | プロセス開始前に成立すべき検査可能な条件 | 開始が妥当または有意味になるために何が既に真であるべきか。 |
| 完了基準 | プロセスを完了とみなす前に成立すべき検査可能な条件 | 終了が許される前に何が真であるべきか。 |

人、エージェント、ツール、システムおよび環境は通常、入力ではなく実行支援要素である。規則がファイルで与えられても、機能上の入力になるとは限らない。その作用に応じて統制事項または制約に分類する。

同じ実物が、別のプロセスでは異なる機能を果たし得る。ファイル種別や他所のラベルではなく、この境界での機能によって分類する。

## 統制事項、制約および実行支援要素

- 方針、基準または判断や評価を方向付ける指示には**統制事項**を用いる。
- 時間、権限、互換性、法令または安全上の限界など、違反できない境界には**制約**を用いる。
- アクセス、専門性、ツール、基盤その他の作業実行に使う能力には**実行支援要素**を用いる。

利用可能な資源をすべて列挙しない。プロセスの理解、実行、組合せまたは評価に必要な機能だけを含める。

## 成果と出力を接続する

成果は成功した状態であり、出力は生み出されたものである。関係が明らかでない場合は、出力が成果をどのように支援または証明するかを示す。

例えば、リスク一覧は出力になり得る。「重要なリスクとその扱いが意思決定者に見えている」は成果になり得る。一覧が関連情報を含み、意思決定の文脈へ届いた場合にだけ成果を支援する。ファイルを作っただけでは不十分である。

すべての成果を必須文書へ変えない。証拠は、変化した状態、観察、メッセージその他の適切な結果でもよい。

## 開始基準と完了基準

出来事やタスクではなく、真偽を検査できる条件として記述する。

- 弱い例: 「依頼を受け取る。」
- より良い開始基準: 「要求された判断とその範囲を識別できる。」
- 弱い例: 「報告書を送る。」
- より良い完了基準: 「意図する受領者が結果と重要な限界へアクセスできる。」

入力、成果または制約で既に解決されていない意味ある曖昧さを取り除く場合だけ基準を追加する。

## スキル間の受け渡し

一つのプロセスの出力が別プロセスの入力になることを意図し、記述しなければ意味が失われ得る場合に受け渡しを記述する。

必要な事項だけを示す。

1. 提供側の出力。
2. 受領側の入力。
3. 維持すべき意味または条件。
4. 受領側に必要な受入条件。

本質的でない限り、転送方法、ファイル形式、リポジトリパスまたは実行統括を規定しない。対応関係を記録するだけの常設台帳を追加しない。

## 結果

曖昧さを取り除く機能上の区別だけを残す。必要な入力と条件が作業を支援し、出力が成果へ接続し、必要な受け渡しが境界を越えて意味を維持することを確認する。
