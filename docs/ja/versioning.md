# バージョン管理

<p align="right">
  <a href="../versioning.md">英語</a> | <strong>日本語</strong>
</p>

ALPSは、`MAJOR.MINOR.PATCH`形式の版番号を用い、リポジトリ全体を一つのリリース単位として扱います。

## リリース単位

ALPSのリリースには、プロセスフレームワーク、ALPS仕様、参照プロセススキル、それらに付随する資源、各言語版、検証スクリプト、リポジトリレベルの文書および資産を含めます。

英語の記述を正本とします。日本語版は同じリリースに含め、対応する英語の正本との整合を維持します。

個々の文書およびスキルパッケージには、独立した版番号を付与しません。リリースの正確な内容は、Gitタグと、そのタグが指すコミットによって特定します。

## 初期開発

`1.0.0`より前の版は、初期開発段階にあります。この期間は、次の規則を適用します。

- `0.1.1`のような`PATCH`リリースには、規範的意味、適用可能性、リポジトリ内のパスに関する契約または機械判読形式を変更しない修正を含めます。
- `0.2.0`のような`MINOR`リリースには、規範的意味、適合基準、必須構造、リポジトリ内のパスに関する契約または機械判読形式の追加、削除または変更を含めます。
- `0.2.0-rc.1`のようなプレリリース識別子は、対応するリリースに至る前の候補版を識別します。

編集上の変更に見える場合でも、規範的効力、範囲、適用可能性または解釈を変更する変更は、`PATCH`ではなく`MINOR`として扱います。`1.0.0`より前の`MINOR`リリースは、以前の版と互換でない場合があります。

## 安定版

版`1.0.0`は、最初の安定した互換性境界を宣言します。`1.0.0`以降は、次の規則を適用します。

- `MAJOR`リリースには、宣言された互換性境界と互換でない変更を含めます。
- `MINOR`リリースには、その境界を破壊しない機能または規範内容の追加を含めます。
- `PATCH`リリースには、後方互換な修正を含めます。

`1.0.0`をリリースする前に、互換性境界および移行について支援する範囲を文書化します。

## 正確な内容の特定

利用者は、必要に応じて次を記録します。

- ALPSの版
- Gitタグ
- コミットSHA
- リポジトリ内のパス
- 個別成果物をより厳密に識別する必要がある場合の内容ダイジェスト

公開したタグは不変とします。公開済みのタグを移動したり、異なる内容に再利用したりしません。ALPSの資産を別のリポジトリへ同期する利用者は、タグとコミットSHAの両方を固定します。

`main`ブランチは、継続中の開発を表します。まだリリースへ割り当てていない変更は、[CHANGELOG.md](../../CHANGELOG.md)の`Unreleased`へ記録します。

## リリース手順

1. 版番号を選択し、`VERSION`を更新します。
2. 完了した項目を`CHANGELOG.md`の`Unreleased`から日付付きのリリース節へ移します。
3. `docs/releases/`にリリースノートを用意します。
4. リリース準備プルリクエストを`main`へマージします。
5. マージコミットに`vMAJOR.MINOR.PATCH`形式のタグを作成します。
6. 用意したリリースノートを用いて、そのタグからGitHubリリースを公開します。
7. タグが意図したコミットを指していることを確認し、その不変性を維持します。
