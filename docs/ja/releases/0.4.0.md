# ALPS 0.4.0

ALPS 0.4.0は、Process ModelおよびProcess View向けのMarkdown Repository／Agent Plugins Bindingを追加する。既定・名前付きModel Entry Point、View資産、互換性宣言、Local／External Skill Source解決および機械的事前検査を標準化し、既存の三つのALPS Reference Skill Identifierを維持する。

## Model／View Binding

Binding Identifierは`alps-markdown-agent-plugins/1.0`である。標準配置は`.alps/MODEL.md`、`.alps/models/<model-id>/MODEL.md`および`.alps/views/<view-id>/VIEW.md`である。

詳細は[markdown-agent-plugins.md](../../.alps/bindings/locales/ja/markdown-agent-plugins.md)を参照する。英語・日本語Templateは`.alps/templates/`配下に収録する。

## ALPS Reference Model

Packageに[`.alps/MODEL.md`](../../.alps/MODEL.md)を追加する。このModelは`define-alps`、`apply-alps`および`manage-alps`の関係を記述する。独立して発動可能なSkillではなく、固定されたLife Cycle順序を定めない。

## 機械的事前検査

- `scripts/check_model_view.py`はBinding構造を検査する。
- `scripts/resolve_model_view.py`は資産Discovery、ALPS互換性評価、Local Skill Source解決およびExternal Plugin Root解決を行う。

これらのToolだけでは、意味的妥当性、Outcome達成、適用妥当性、採用またはExecution Conformanceは成立しない。

## Reference Skill変更

- `define-alps`はModel／ViewのNeed Identification、DesignおよびVerificationを扱う。
- `apply-alps`は既定または選択Modelを解決し、互換性のあるViewを適用し、SourceおよびHandoff Identityを維持する。
- `manage-alps`はModel／Viewの採用、互換性、変更、Releaseおよび廃止を管理する。

## Compatibility

本BindingのALPS互換性Rangeは`>=0.4.0 <0.5.0`である。既存のSkill IdentifierおよびRoot `skills/` Pathは変更しない。ModelまたはViewを含まないPackageも引き続き有効である。名前空間付きAgent Plugins Extensionを理解しないClientは無視してよい。

Tagおよび公開Releaseは、Release CandidateのReviewとMerge後に別Actionとして作成する。
