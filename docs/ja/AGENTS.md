## ALPS

このリポジトリには、ALPSに基づいてプロセスフレームワークの概念を表現するエージェントスキルが含まれます。

ALPSは通常のプロセスから始まります。エージェントスキルは既定では、正本となるプロセス記述によってプロセスを表現します。ALPSではさらに、エージェントスキルによってプロセスモデル、プロセス参照モデル、プロセスビューを表現できます。これらプロセス以外の表現は`metadata.alps.kind`で識別します。表現の読込みは選択・構成の文脈を読み込むものであり、それ自体はプロセスの呼び出しではありません。

ALPS参照モデルは`alps-reference-model`で表現し、Define ALPS、Apply ALPS、Manage ALPSの三つの参照プロセスを定義します。これらは固定段階ではなく、適用状況に応じて選択、組み合わせ、反復または再適用できます。

### ALPSの使い方

- ALPS参照モデルを参照プロセスの選択、関係付け、アセスメントまたは改善に用いる場合は`alps-reference-model`を読み込みます。
- エージェントスキルは既定ではプロセス表現として扱います。`metadata.alps.kind`が`process-model`、`process-reference-model`または`process-view`を宣言する場合は、その表現を読み込み、その読込みをプロセスの呼び出しとして扱いません。
- 選択した各表現について、依存する前に完全な`SKILL.md`を読みます。
- プロセス記述、プロセスモデル、プロセス参照モデル、プロセスビューを含むALPS表現の定義・検証には`define-alps`を用います。
- 適用するモデルまたはビューの読込み、参照プロセスの解決、プロセス表現だけの呼び出し、必要な受け渡しの管理には`apply-alps`を用います。
- 管理対象表現の採用、状態、統制された変更、テーラリング、正式採用、アセスメント、改善、廃止には`manage-alps`を用います。
- 参照プロセスへ依存する前に正規のスキル参照を解決します。リポジトリ相対パスを表現の識別情報の代替として用いません。
- プロセスビューで出典プロセスの要素を参照する場合は来歴と追跡可能性を維持し、ビュー固有または変更された活動やタスクを出典プロセスの変更として扱いません。

## リポジトリの作業フロー

- 原則としてリポジトリのルートでは`main`を維持します。ユーザーの明示指示がない限り、開発作業は`.worktrees/<branch-name>`内の`<type>/<topic>`ブランチで行います。
- `<type>`には変更の性質を指定し、作業者、エージェントまたはツールを指定しません。`feat`、`fix`、`docs`、`refactor`、`test`、`build`、`ci`、`chore`などを優先し、`<topic>`は簡潔なケバブケースで記述します。
- 編集前にリポジトリの状態を確認し、無関係な変更およびユーザー変更を保持します。
- 一つの情報項目につき正本となる出典を一つにします。プロセスフレームワークが複数表現で同じ意味上の中核を要求する場合、差異に優先順位を与えるのではなく機械的に一致を検証します。
- 一方の言語版を変更する場合は、対応する英語版または日本語版への影響を評価します。
- ユーザーから依頼されない限り、コミット、プッシュ、公開、プルリクエスト作成その他の外部変更を行いません。
- 選択した表現の検証要求に従います。最低限、`git diff --check`、変更した相対リンクの確認、適用されるALPS資産検査、今回の作業に属する最終差分の確認を行います。実行しなかった必須検査がある場合は、その項目と理由を報告します。
