# ランタイムと製品の境界

[英語の原文](../../runtime-product-boundary.md)

ALPSは、単独で利用できる公開ランタイムとプラグインを維持する。製品は、公開された接続契約を通じて、リビジョンを固定したランタイムを利用する。製品UI、デスクトップシェル、導入体験、任意のサービス連携は別に開発できる。ランタイムは製品コードを取り込まず、非公開リポジトリへのアクセスを必要としない。

## 責務

| 公開ALPSランタイム | 製品 |
| --- | --- |
| プロセス定義、Skills、CLI、各ホストのプラグイン／MCPアダプター | 製品UI、ナビゲーション、デザインシステム |
| インスタンス生成、実行、評価、アセスメント、来歴 | 公開APIを通じた表示と操作文脈に応じたアクション |
| ワークスペースの所有と、ハーネス記録の唯一の書き込み主体 | ワークスペースの選択とランタイムのライフサイクル連携 |
| 依頼の範囲、開始確認、完了、継続、取り消しの規則 | 実行の意図と、開始／確認場所を分けた選択 |
| 接続契約、スキーマ、対応機能、任意の観測アダプター | 互換性確認、設定、診断、任意のローカル収集 |
| 任意の参照Web UI | 別にビルドする製品UIとデスクトップ配布 |

製品は、実行や保存の実装を自分のリポジトリへ複製してはならない。ランタイムのワークスペース所有、権限、再試行時の重複防止、範囲制約を維持しなければならない。観測情報はランタイムのインターフェースを通して共有し、別の書き込み主体が記録ファイルを更新しない。

## 実行と確認

計画と実行の選択は範囲の判断である。CLIとデスクトップアプリの選択は開始方法である。記録済みのログをターミナルで開くことは確認操作である。これらを分けて扱う。ウィンドウを開いても依頼の開始確認や作業範囲の拡大にはならず、ログを再度開いても別のエージェントを起動しない。

依頼の記録は実行より前に存在し得る。送信失敗や利用できない接続は、実行を捏造せずに確認できなければならない。MCP初期化の成功は通信とツール利用可能性を確認するが、ホストは作業前に保存済み依頼の開始確認を行う必要がある。接続が切れたデスクトップ実行は、再接続または明示的な報告で解消するまで外部の実行状態が不確かである。

目覚めはオーケストレーションの契機であり、インスタンスではない。複数のインスタンスを生成し、複数の実行を開始し、あるいは新しいインスタンスなしで報告を残すことがある。インスタンスとアセスメントの記録は各対象に紐づけたまま、相互に辿れるようにする。この境界は、未記録の判断や人の承認状態が既に存在するという主張を追加しない。

## 記録と観測

ALPS記録は、ハーネスが受け付けて記録した事実を示す。プロバイダーの会話記録は、会話と保持されている内容を提供できる。OpenTelemetryは、出力・収集された範囲のイベント、エラー、時間、使用量を提供する。実行完了もトレースも、プロセスの成果達成を証明するものではない。

ALPSの依頼／実行／インスタンスID、プロバイダーの会話ID、MCP接続ID、トレース／スパンIDは異なる対象を識別する。紐づけでは、この区別と、収集元、期間、判明している欠落、内容の収集方針を保持しなければならない。一つの会話が複数のALPS実行を含むことがある。観測情報の欠落や利用できない会話内容は不明であり、ゼロや作業がなかった根拠ではない。ハッシュやアプリへのリンクだけでは旧版を保持できない。

観測は任意である。収集サービスの停止が、作業の開始、開始確認、完了報告、保存を妨げてはならない。製品の初期収集方針では、依頼本文、ツールの内容、無関係なセッションを除外する。実際のホストとBunでの連携を確認する必要があり、文書上の対応だけではそのPCでの一連の動作を確認したことにならない。
公開ランタイムの任意テレメトリー出力は、許可された相関属性と短いワークスペース識別子だけを使う。ワークスペースの絶対パスや、収集側から渡された任意属性は既定では外部へ出力しない。

## 配布と互換性

ランタイムはUIをビルドせずに起動できる。参照UIと製品UIは、同じランタイム上で明示的に選ぶ表示方式である。必要な機能をランタイムが宣言している場合、ユーザー認証済みの製品は、同じワークスペースで既に動いているヘッドレスランタイムへ自分のUIエントリーを接続できる。この接続は`server.json`に記録される表示エントリーだけを変えるものであり、デーモンを止めたり、ランタイムを複製したり、非公開コードを公開ランタイムへ取り込んだり、ランタイムの書き込み主体を変えたりしてはならない。製品は操作を有効にする前にAPI、イベント、保存形式の契約と必要な対応機能を確認し、配布するランタイムのリビジョンを固定する。ソースのチェックアウト、インストールされたプラグイン、ワークスペースの設定は異なる場所にある。展開されていないホスト固有変数をプロジェクトのパスに使ってはならない。

既に公開されたコードには、適用されるライセンスが引き続き適用される。ランタイムや派生アセットの配布では、該当するライセンス、NOTICE、変更表示を保持する必要がある。今後の製品開発を分けても、公開コードについて既に与えた権利は取り消されない。

成果物配信と新しい形式別プレビュー基盤は、別の設計対象として維持する。この分離は既存の成果物へのアクセスと評価要件を保持するものであり、Office／PDFの再現精度、スナップショット保持、新しいプレビュー対応を実証するものではない。
