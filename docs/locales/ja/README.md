繰り返し行うエージェント作業は、一度限りのプロンプトや案件固有の手順から始まることが少なくありません。そのままでは、作業の理由が暗黙のままになり、成功を評価しにくく、一案件の詳細と再利用すべき知識が絡み合います。ALPSは、正本となるプロセス記述を設計し、その作業を明確で再利用可能なプロセススキルへ整えます。

ALPSは、エージェントスキルの作成者、反復作業を標準化するチーム、実際の利用結果から既存スキルを簡素化する保守担当者のためのものです。配布する唯一のスキル[`design-process-description`](../../../skills/design-process-description/references/locales/ja/SKILL.md)は、一つの目的、観察可能な成果、一貫した再利用可能な境界、および正確で安全かつ意味があり、組み合わせと評価が可能な利用に必要な最小限の詳細を明確にします。

## 対象となる利用者

次のような場合にALPSを利用します。

- 反復作業を、複数回の適用を導けるプロセス記述へ整えたい。
- 作業が存在する理由と、観察可能な成功状態を明示したい。
- 再利用可能なプロセス知識を、案件固有の担当者、ツール、ファイル、リポジトリ、値および実行順序から分けたい。
- 利用結果、失敗、繰り返された確認、未解決の仮定および既知の限界に基づいて、既存のプロセススキルを改訂したい。

## ALPSを使うと何が変わるか

| 利用前 | ALPSの利用後 |
| --- | --- |
| 一度限りのプロンプトや手順が一案件に結び付いている。 | 再利用可能なプロセス記述が、一つの一貫したプロセス境界を定める。 |
| 成功条件が暗黙のままである。 | 一つの目的が作業の存在理由を示し、観察可能な成果が成功状態を示す。 |
| 担当者、ツール、ファイル、リポジトリまたは固定順序がプロセスそのものとして扱われる。 | 再利用可能なプロセス知識を、実装と一回の適用文脈から独立させる。 |
| 必要性の根拠がないまま指示が増えていく。 | 正確性、安全性、意味、組合せ可能性または評価可能性に必要な詳細だけを残し、利用証拠に基づいて簡素化する。 |

## クイックスタート

### 1. プラグインをインストールする

ALPSは[Agent Plugins](https://agent-plugins.org/) v1パッケージとして配布します。Node.js 18以降の環境で実行します。

```console
npx plugins add mashimashica/alps
```

インストール済みスキルの再読込みが必要なクライアントを再起動してください。

### 2. プロセス記述を設計または再設計する

反復作業のプロセス記述を作成、改訂または簡素化するときに[`design-process-description`](../../../skills/design-process-description/references/locales/ja/SKILL.md)を使用します。通常はこの`SKILL.md`だけで十分です。特定の設計判断に詳しい情報が必要な場合にだけ、該当する一つの参考資料へ進みます。

反復作業そのものを実行するときは、対象のプロセススキルを直接適用します。

### 3. エージェントに依頼する

```text
この反復的なインシデント要約作業を、一つの目的、観察可能な成果および一貫した境界を持つ再利用可能なプロセス記述にしてください。

このプロセススキルで、再利用可能な知識を案件固有の担当者、ツール、ファイル、リポジトリおよび固定順序から分けてください。正確で評価可能な利用に必要な詳細だけを残して簡素化してください。

添付した利用結果、失敗、繰り返された確認、未解決の仮定および既知の限界を用いて、このプロセス記述を改訂してください。
```

このスキルは、不明点を推測で補わず、作成または改訂したプロセス記述とともに、未解決事項、明示した仮定および既知の限界を提示します。

## 仕組み

プロセス記述は、明確な名称、一つの目的および観察可能な成果から始めます。次に、反復作業の一貫した境界を定め、持続的なプロセス知識を個別の適用で与える情報から分けます。

活動、タスク、入力、出力、条件および受け渡しは、省略するとプロセスが曖昧、安全でない、組み合わせにくい、または評価できない場合にだけ追加します。不要な実行者、ツール、方法、指標、ファイルパス、リポジトリ詳細、固定順序および特殊事例分岐は削除します。

通常の`SKILL.md`は、必要な場合だけ三つの独立した参考資料へ案内します。

| 設計上の問い | 参考資料 |
| --- | --- |
| このプロセスは何のために存在し、どの状態が成功を示すか。 | [目的と成果](../../../skills/design-process-description/references/locales/ja/purpose-and-outcomes.md) |
| 再利用可能なプロセスに何を含め、一回の適用側へ何を残すか。 | [境界と詳細](../../../skills/design-process-description/references/locales/ja/boundary-and-detail.md) |
| 周囲にある項目や条件はどの機能を果たすか。 | [入力、出力および条件](../../../skills/design-process-description/references/locales/ja/inputs-outputs-and-conditions.md) |

## 対象範囲

プロジェクト名の「ライフサイクル」は、繰り返し利用し、得られた知見から再設計することを表し、ライフサイクル状態機械を導入するものではありません。ALPSは対象スキルのプロセス記述を設計します。対象プロセスの実行、常設のスキル選定や実行統括、Gitやリリースの管理、形式的な適合主張または認証は行いません。
