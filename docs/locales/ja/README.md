ALPSは、[プロセスフレームワーク](../../../spec/process-framework.md)を
[Agent Skills](https://agentskills.io/specification)へ適用する薄いプロファイルです。
反復または共有されるエージェント作業を、明示的な目的、観測可能な成果および
適用に必要な手引きだけを持つ、再利用可能で評価可能なプロセススキルとして
確立できるようにします。

プラグインおよびリポジトリのブランド名は`alps`です。配布スキルの識別子は
`reusable-work-design`です。プロセス名称は
[`再利用可能な作業設計プロセス`](../../../skills/reusable-work-design/references/locales/ja/SKILL.md)
（英語では`Reusable Work Design Process`）です。

## ALPSが扱う問題

| 反復作業で生じる問題 | ALPSによる対応 |
| --- | --- |
| 反復プロンプトは動作しても、その意図と完了の定義が人の頭の中に残る。 | 一つのプロセス目的と観測可能な成果を示す。 |
| 文書を作成したことを、作業が成功した証拠として扱う。 | 出力と、成果が表す成功状態とを区別する。 |
| 一つのスキル境界が、互いに無関係な作業理由を結合する。 | 一つの整合したプロセス境界を確立し、独立した目的を分離する。 |
| 一般スキルが、必要もなく実行主体、ツール、方法、測定量または順序を固定する。 | 実際の統制事項または制約が要求しない実装上の選択を固定しない。 |
| スキル間の情報交換が暗黙の文脈に依存する。 | 記述対象となる提供側出力から受領側入力への受け渡しを明示する。 |
| テンプレートの完成または形式検査の通過を、品質の証明として扱う。 | 形式検査、意味レビューおよび実行アセスメントを区別する。 |

ALPSは、ホストによるスキルの発見、選択、有効化または実行を包み直しません。
リポジトリまたは組織による採用、版管理、統制された変更または廃止も統治しません。

## 配布スキル

ALPSが配布するエージェントスキルは一つです。

| スキル識別子 | プロセス名称 | 目的 |
| --- | --- | --- |
| [`reusable-work-design`](../../../skills/reusable-work-design/references/locales/ja/SKILL.md) | 再利用可能な作業設計プロセス | 反復または共有されるエージェント作業を、再利用可能かつ評価可能なプロセススキルとして確立する。 |

次の場合に使用します。

- 安定した意図と成功の定義が必要な反復作業
- 複数の利用者またはエージェントが理解する必要のある共有作業
- プロセス間の受け渡しを明示する必要のある組合せ作業
- レビューまたは改訂が必要な既存プロセススキル

次の場合に単に使用するものではありません。

- 具体的な再利用、共有、組合せ、レビューまたはアセスメントのニーズがない
  一回限りの作業
- 定義済みスキルが表すプロセスの通常実行
- ホストが既に提供する一般的なスキルの発見または選択
- 採用済みスキルに対するリポジトリまたは組織の統治

## 意味上の中核から始める

すべてのプロセス記述は、次の三要素から始まります。

| 要素 | 答える問い |
| --- | --- |
| **名称** | どの中心的な関心によって、このプロセスを識別するか。 |
| **目的** | なぜ、このプロセスを実行するか。 |
| **成果** | どの観測可能な結果状態を成功とみなすか。 |

任意の詳細は、存在しないことで正しい発見、適用、組合せまたはアセスメントが
実質的に損なわれる場合にだけ追加します。任意の詳細には、活動、タスク、入力、
出力、開始基準、完了基準、統制事項、制約、実行支援要素、受け渡しおよび
アセスメントに必要な証拠を含めることができます。

[再利用可能な作業設計プロセス](../../../skills/reusable-work-design/references/locales/ja/SKILL.md)
自体を主要例とします。ALPSは、すべての節を並べたテンプレートを意図的に提供しません。
空欄または不要な節があることは、完全性の証拠になりません。

## 主要な区別

| 区別 | 意味 |
| --- | --- |
| **成果／出力** | 成果は成功した状態であり、出力は生産または引き渡される項目、結果またはサービスです。 |
| **入力／実行支援要素** | 入力は変換される項目です。エージェント、人、モデル、ツールおよび実行環境は実行を支援します。 |
| **記載順／実行順序** | 文書内の活動またはタスクの順序は実行順序を規定しません。実際の時間的関係は制約です。 |
| **ブランド／プロセス名称** | `alps`はプロジェクトとプラグインの名称です。プロセス名称は作業の中心的な関心を表します。 |
| **自己適用／自己認定** | プロセススキルを自身の設計規則でレビューできますが、そのレビューは適合の独立した証明ではありません。 |

## 責任分担

| 担当 | 責任 |
| --- | --- |
| Agent Plugins | プラグインを配布し、可搬な発見面を提供する。 |
| Agent Skillsホスト | スキルを発見、選択、有効化および実行する。 |
| 再利用可能な作業設計プロセス | 再利用可能なプロセススキルを作成、レビューおよび改訂する。 |
| 得られた各プロセススキル | 表現するプロセスの実行に必要なプロセス記述を提供する。 |
| リポジトリまたは組織 | 採用、版管理、統制された変更、廃止および統治を判断する。 |

## インストールおよび利用

ALPSは[Agent Plugins](https://agent-plugins.org/) v1パッケージとして配布します。
Node.js 18以降の環境で`plugins` CLIを使用してインストールします。

```console
npx plugins add mashimashica/alps
```

インストール後は、対象クライアントがエージェントスキルを再読込みできるように
再起動します。ホストが明示的な有効化を必要とする場合はスキル名を指定し、
日常語で依頼します。

```text
reusable-work-designを用いて、この反復的なリリースレビュー作業を、再利用可能な
プロセススキルにしてください。一つの境界、明示的な目的、観測可能な成果、および
適用とアセスメントに必要な詳細だけを確立してください。
```

## 仕様の境界

一般的なプロセス意味論は、[プロセスフレームワーク](../../../spec/process-framework.md)
を正本とします。[ALPS仕様](../../../spec/ALPS-SPEC.md)は、エージェントスキルへの
薄い適用プロファイルです。スキルの物理形式はAgent Skills specificationによって
定まります。

形式検査、構文解析、ロード、スキルの有効化、テンプレートの完成または文言上の
自己主張だけでは、
意味上の適合、成果達成またはプロセス実行の適合を成立させません。
