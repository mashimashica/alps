## 1. プロセススキルの例

次の例では、ファイル形式のエージェントスキル表現を用いる。物理形式は例示であり、意味上の区別が重要である。

```markdown
---
name: consolidate-meeting-minutes
description: 会議記録から決定事項、アクション項目および未解決事項を抽出し、出典記録への追跡可能性を維持した議事録を作成する。会議記録の整理、議事録の作成または会議後の対応整理を依頼された場合に使用する。ALPS準拠。
---

# 会議議事録整理スキル

## 目的

このプロセスは、会議記録から決定事項、アクション項目および未解決事項を区別できる状態を確立する。

## 成果

- 会議で行われた決定が識別されている。
- アクション項目およびその期限が識別されている。
- 未解決事項が識別されている。
- 整理した内容と出典記録との対応が追跡可能である。

## 活動とタスク

記載順は実行順序を規定しない。

### 記録の把握

1. 整理範囲および記録の欠落を識別する必要がある。
2. 不明確な記述を推測で補ってはならない。
3. 秘密情報の取扱いに適用する方針を適用する必要がある。
4. 通常、参加者および議題の一覧を確認する。

### 項目の抽出

1. 決定、アクション項目および未解決事項を区別して識別する必要がある。
2. 出典記録にない決定を出力に含めてはならない。
3. 各アクション項目に期限を対応付けるのが望ましい。
4. 項目に優先度分類を付けてよい。

### 検証可能性の確立

1. 抽出した項目と出典記録との対応を維持する必要がある。
2. それらの対応を確立した後にだけ、出力を引き渡す必要がある。
3. 出典記録から確認できない項目は、確認を要するものとして明示するのが望ましい。

## 入力

メモ、書き起こしおよび配付資料を含む会議記録。

## 出力

整理した会議議事録。

## 開始基準

- 会議記録を利用できる。
- 整理範囲が示されている。

## 完了基準

- すべての成果の達成状況が判定されている。
- 出力が受領者に引き渡されている。

## 統制事項

- 秘密情報の取扱いに適用する方針。

## 制約

- 出力は、出典記録によって裏付けられる決定、アクション項目および未解決事項に限定する。
- 抽出した項目と出典記録との対応を確立した後にだけ、引渡しを許可する。

## 実行支援要素

- 書き起こし支援ツール
- 分野用語集
- 実行主体の自然言語処理能力

## 一般的な進め方

この節は参考情報であり、規範的効力を持たない。

- 決定は、合意または承認を示す表現の近くに現れることが多い。
- 長い記録では、議題ごとに反復できる。
```

整理した議事録は出力であり、成果ではない。引渡し条件は制約であり、対応する引渡し行為はタスクである。ツールおよび実行主体の能力は、入力ではなく実行支援要素である。

## 2. ファイル形式のスキルパッケージ例

環境への対応付けは、ALPSが定める論理上の役割を変更せず、スキルパッケージをファイルとして表現できる。

```text
<skill-name>/
├── SKILL.md
├── references/
│   └── <reference>.md
├── scripts/
└── assets/
```

| 構成要素 | 代表的なALPS上の扱い |
|---|---|
| `SKILL.md` | 正本となるエージェントスキル表現。プロセスでは本文が正本のスキル記述を提供し、発見情報をフロントマターまたは別の登録情報へ投影してよい。 |
| `references/` | 必要に応じて読み込む参考情報。個々のファイル名をALPSは規定しない。 |
| `scripts/` | 再現性または信頼性を支援する実行資源。通常は実行支援要素として扱う。 |
| `assets/` | 出力の作成または適用の支援に用いる資源。機能に応じて分類する。 |

格納区分は任意である。パッケージには、表現するPF構成概念の理解または適用を直接支援する資源だけが必要である。

### 3.3 関連するライフサイクル規格

次の規格は、関連分野のライフサイクルプロセスまたはプロセス記述を扱う。

- ISO/IEC/IEEE 12207 — ソフトウェアライフサイクルプロセス
- ISO/IEC/IEEE 24774:2021 — プロセス記述の仕様

これらは、当該規格も利用する読者のための参考文書である。ALPSおよびプロセスフレームワークは独自に作成されており、ALPSへの適合は、これらの規格への適合を要求せず、または確立しない。ALPSは、それらの発行組織によって開発、承認または認証されたものではない。

## 4. PFとALPSの責務分担

一般的なプロセス構成概念は、すべてPFを正本とする。ALPSは、エージェントスキル表現またはALPSライフサイクルに追加規則が必要な場合だけ、それらを特殊化する。

| PFの主題 | PFの規範上の責務 | ALPSによる特殊化 |
|---|---|---|
| 作業およびプロセス記述 | プロセス、プロセス記述、プロセスインスタンス、必須の意味上の中核、層および記述規則 | スキル記述ならびに発見層および実行層 |
| 意図および作業内容 | 名称、目的、成果、出力、活動およびタスク | エージェント向け発見情報の整合性、ならびにタスクの操作と対象の区別 |
| プロセス境界 | 粒度、一体性、実行主体からの独立性および選択 | プロセススキルとプロセスビューとの表現境界 |
| 境界要素および受け渡し | 入力、出力、統制事項、制約、実行支援要素、基準、受け渡しおよび追跡可能性 | スキルパッケージ資源の役割およびスキル間の組合せ |
| 再利用可能な構造 | プロセスモデル、プロセス参照モデル、プロセスフレームワーク、ライフサイクルモデルおよびプロセスビュー | 表現種別およびALPS参照モデルの整合性契約 |
| 組合せ適用 | 並行、反復、再帰および統合 | 読込み、プロセス解決、呼び出しおよびエージェントスキルの組合せ |
| 適応 | テーラリングおよびプロセスのインスタンス化 | ALPS参照プロセスを通じた管理されたテーラリングおよび正本の再定義 |
| 証拠および主張 | 意思決定ゲート、レビュー、監査、プロセス適合および能力 | ALPS固有の適合対象および表現アセスメントの境界 |
| 管理および改善 | 一般的なプロセス統治、測定、ベンチマーキングおよび学習 | ALPS参照ライフサイクルとしてのDefine ALPS、Apply ALPSおよびManage ALPS |

## 5. 人による監督、説明責任および証拠

### 5.1 人による監督の構成

人による監督は、独立したスキル記述要素ではない。監督を必要とする適用状況では、次の要素を組み合わせて表現できる。

- 実行または判断を方向付ける統制事項
- 許容される実行を制限する制約
- 人の能力を提供する実行支援要素
- 呼び出しおよび完了を条件付ける開始基準および完了基準
- 不可逆または高影響の行為の前に置く意思決定ゲート
- 実行および判断の記録
- Apply ALPSおよびManage ALPSで行う判断

適用状況は、リスク、影響、可逆性、不確実性ならびに関係する人およびエージェントの能力から、監督の形態、介入条件および粒度、判断権限ならびにエスカレーション経路を定める。

非決定性、創発的挙動、監督者の認知負荷、自動化バイアスおよび不明確な責任関係は、監督を困難にし得る。これらはエージェント文脈上の考慮事項であり、PFの一般意味論ではない。

### 5.2 追跡可能性および説明責任

**追跡可能性**は、入力、判断、タスク、出力、証拠および変更の関係をたどれる性質である。

**説明責任**は、特定のプロセスインスタンスについて、判断権限、監督責任または説明義務を誰が持つかを定める関係である。

追跡可能性は説明責任を支援するが、責任を割り当てない。一般的なプロセス記述は、実行主体または組織を固定しない。プロセスインスタンスでは、必要な責任、権限、承認者およびエスカレーション経路を識別できる。ログおよび監査証拠は、事後の検証と責任関係の明確化を支援する。

### 5.3 人の能力

人の専門性、判断および介入能力は、実行支援要素になり得る。認知負荷、応答時間および監督者の利用可能性は、制約になり得る。必要な監督能力を利用できない場合、開始基準を満たさないことがある。

一つのプロセスインスタンスへの適合は、監督者または監督体制の一般的な能力を確立しない。高い能力のアセスメントも、一つの実行への適合を確立しない。

ALPSは、人の能力水準、成熟度モデルまたは認証制度を定めない。

### 5.4 非決定的なプロセススキル

非決定的挙動に対しても、成果および適合の定義は変わらない。リスクに応じた表現検証、成果証拠およびテーラリングを、次のように適用できる。

- 変動が重要な場合、一回の実行だけを成果達成可能性または能力水準の十分な証拠として扱わない。
- 代表的な利用状況には、境界条件、異常条件および新規状況を含める。
- 一意の期待結果を定義できない場合は、受入れ条件、禁止条件または評価方法を代わりに定める。
- 実行記録に、観測した変動、証拠の限界および未解決の不確実性を残す。
- 反復試行または継続監視の必要性は、品質リスクから決定する。

非決定性および一つの期待結果を定められないことは、検証と人による監督の双方を難しくし得る。

### 5.5 監督結果のManage ALPSへの返却

Apply ALPSは、次の代表的な情報を、実行記録および教訓としてManage ALPSへ引き渡すことができる。

- 人による承認および介入の記録
- 介入を必要とした条件
- 人がエージェントの提案を変更または却下した事例
- 人が検出できなかった失敗
- 説明またはログが判断に不十分だった事例
- 自動化バイアスまたは過剰介入の兆候
- 監督者の負荷および応答遅延
- 意思決定ゲートの過剰または不足
- 使用した証拠の品質および限界
