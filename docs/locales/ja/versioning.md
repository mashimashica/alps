# バージョン管理

<p align="right">
  <a href="../../versioning.md">英語</a> | <strong>日本語</strong>
</p>

ALPSは`MAJOR.MINOR.PATCH`形式の版番号を用い、リポジトリ全体を一つの単位としてリリースします。

## リリース単位

一つのリリースには、単一の配布スキルと参考資料、英語および日本語文書、Pluginおよびホストマニフェスト、リポジトリ検証、ならびに維持するブランド資産と法的資産を含めます。個別のファイルやスキル資源には独立した版番号を付けません。

正確なリリース内容は、不変のGitタグと、そのタグが示すコミットによって特定します。英語の利用者向け資産を正本とし、対応する日本語版を同じリリースに含めて意味を整合させます。

## 初期開発

`1.0.0`より前の版は初期開発段階です。

- `PATCH`リリースは、公開上の意味、必須構造、リポジトリパス契約または機械判読形式を変えない修正です。
- `MINOR`リリースは、公開上の意味、必須構造、リポジトリパス契約または機械判読形式を追加、削除または変更でき、以前の1.0未満の版と互換でない場合があります。
- `0.6.0-rc.1`のようなプレリリース識別子は、対応するリリースの候補を示します。

## 安定版

`1.0.0`で最初の安定した互換性境界を宣言します。それ以降、非互換変更には`MAJOR`、互換性を保つ機能には`MINOR`、後方互換な修正には`PATCH`を用います。

## 内容の特定

利用者は必要に応じて、ALPSの版、Gitタグ、コミットSHA、リポジトリパスおよび成果物ダイジェストを記録できます。公開したタグは移動または再利用しません。`main`ブランチは継続中の開発を表し、未確定の変更は[CHANGELOG.md](../../../CHANGELOG.md)の`Unreleased`に記録します。

## リリース手順

1. 版を選び、`VERSION`とすべてのPluginマニフェストを更新します。
2. `CHANGELOG.md`へ日付付きの節を追加し、`docs/releases/`へリリースノートを用意します。
3. リポジトリの通常検証を実行し、最終差分をレビューします。
4. リリース状態をコミットします。
5. 公開が承認されたときは、そのコミットへ`vMAJOR.MINOR.PATCH`形式のタグを付け、対応するリリースノートを公開します。
6. タグが意図した不変のコミットを示すことを確認します。
