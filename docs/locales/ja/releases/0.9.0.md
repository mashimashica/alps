# ALPS 0.9.0

[English source](../../../releases/0.9.0.md)

ALPS 0.9.0では、一つのプロセスモデルを一つのAgent Pluginとして作成する`create-process-models`を追加します。モデルの構成員、表示名、型付き入出力、共有定義を明示します。また、サービス評価の実例における数値の境界比較を修正します。

## プロセスモデルの作成

[create-process-models](../../../../skills/create-process-models/references/locales/ja/SKILL.ja.md)は、関係する仕事を、一貫したプロセスの責務、観察可能な成功条件、共有する情報の関係へ整理します。依頼の範囲内でパッケージの正本を作成し、その整合性を検証します。案内と参照資料は自己完結しており、既存の二つの設計Skillとは独立して使えます。

Pluginは、`design-process-description`、`design-agent-work-system`、`create-process-models`の三つのSkillを配布します。日英の案内、リポジトリ内の発見経路、検証、Codexの表示情報に新Skillを追加しました。両READMEでは、使いどころ、渡す情報、生成するファイルを説明しています。

## 一つのモデルを一つのPluginに

[モデル形式](../../../../skills/create-process-models/references/locales/ja/model-format.md)で、ALPSモデルプロファイルの版1を導入します。

- `plugin.json`のALPS拡張に、モデルの構成員を明示的に列挙します。Hostが発見しただけでは、補助Skillはモデルの構成員になりません。
- 列挙された各プロセスMarkdownが、記述の全文、安定した識別子、表示名、入出力宣言の正本です。Agent Skillは`skills/<name>/SKILL.md`に置き、人の仕事など、それ以外の仕事には通常のMarkdownを使えます。
- `references/artifacts/<id>.md`に、入出力から参照する情報項目・製品・サービスを共有定義します。具体的な成果物のパスと実行設定は、任意のワークスペース設定で扱います。

登録されたすべてのプロセス文書には、文書の言語による、空白だけではない文字列の`metadata.title`が必要です。安定した識別子やH1は、この表示名の代わりにはなりません。この要件は、未登録の補助Skillや成果物の型定義には及びません。宣言する`metadata.inputs`と`metadata.outputs`は、型識別子のJSON配列を文字列として符号化します。

グラフはこれらの正本の投影です。別のモデルファイル、型レジストリ、目的と成果の複製は導入しません。循環を許容し、入出力関係だけでは実行順序を指定せず、承認、準備完了、成功を確立しません。基準・方針・要求は、原記述で、仕事を規定する統制事項としての意味と適用可能性を維持します。形式には、統制事項専用のメタデータ項目やエッジ区分を設けません。モデル作成の案内は、アプリケーションの表示・実行・評価の実装とは分けています。

## 実例と文書の修正

[サービス評価の実例](../../../../examples/locales/ja/README.md)では、十進数の時間上限とエラー件数の比率を厳密に比較し、丸めによって境界を含む判定が変わることを防ぎます。出力するJSONの数値には丸めが生じる場合がありますが、判定の真偽値はその変換前に計算します。ツールの案内でこの区別を説明し、比較の回帰検証を追加しました。Pythonの要件は引き続き3.10以降です。

READMEのリリースノート参照を`VERSION`と照合する検査を追加しました。翻訳manifestには、本リリースの日本語ノートを含め、レビューした英語原文を記録します。

## 0.8.0からの更新

Plugin全体を更新し、クライアントを再読み込みしてください。三つのSkillが表示され、それぞれの参照リンクを開けることを確認します。Plugin名`alps`と、既存の二つのSkillの識別子・パスは変更していません。個別に配布する場合は、各Skillのディレクトリ全体を保持してください。

モデルプロファイルを採用する場合は、manifestの明示的な構成員、各プロセスの`metadata.title`、文字列化した入出力配列、対応する共有定義を確認してください。既存モデルの変換では、正本と影響する参照を明示的に変更します。プロファイルは旧形式へのフォールバックを定めていません。パッケージの検査に通っても、モデル化した仕事の実行成功を証明するものではありません。

新Skillと機械が解釈するモデルプロファイルを追加するため、[版管理方針](../versioning.md)に基づく1.0未満のMINORリリースです。プロファイルの版`1`は、ALPSのリリース版`0.9.0`や、作成する各モデルPlugin自身のリリース版とは別です。

公開後は、再現性のため`v0.9.0`タグと、そのタグが指すコミットSHAを記録してください。詳しい変更は[CHANGELOG](../../../../CHANGELOG.md)に記載しています。
