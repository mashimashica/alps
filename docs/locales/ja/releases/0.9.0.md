# ALPS 0.9.0

[English source](../../../releases/0.9.0.md)

ALPS 0.9.0では、プロセスモデルを具体的な仕事に適用するハーネスを追加しました。ハーネスはプロセスをエージェントで実行し、その実行と、成果の評価を記録します。ハーネスは、仕事の意味であるプロセスモデルとSkillを読むだけで、変更しません。各成果の判断は、実行の終了とは別に扱います。

## ハーネス

ハーネスは、具体的な入力、出力の置き場所、その適用での各成果の意味を定めて、プロセスをインスタンス化します。インスタンスをClaude Code、Codex、デモのエージェント、または呼び出し元のセッションで実行し、各実行を、使った入力と、各出力をどの実行が作ったかとともに記録します。評価は、成果ごとに判断（達成、未達成、未確認）、その根拠と限界、判断者を記録します。判断者は、WebUIからの人か、MCPクライアントで識別されるエージェントです。判断した実行を同じセッションが行っていた場合は、その旨を記録します。評価の入力のいずれかか`SKILL.md`が、判断した実行が使った内容とSHA-256で一致しなくなると、その評価は根拠が古いと示されます。

英語と日本語のWebUIは、プロセスとアーティファクトの型のネットワーク、ダッシュボード、インスタンスを示します。ダッシュボードが数えるのは三値の判断だけです。実行が終わったこと、出力があること、エージェントが報告したことは、どれも成果の達成になりません。所見は三種類です。記述の問題（どのプロセスも作らないアーティファクトの型など）は`design-process-description`へ、構成の問題（見つからないSkill、起動できないエージェントなど）は`design-agent-work-system`へ渡すためのものです。もう一つは未確認の事項（判断を待つ実行、根拠が古い評価など）です。

エージェントは、MCPサーバーの12のツールと五つのリソースを通じてハーネスを使います。`schedules`で定めた時刻に、または求めに応じて目覚めたエージェントは、モデル、Markdownの案内、現状を読み、どのプロセスを走らせるかを判断します。ハーネスは順序を課しません。`run-process` Skillは、セッション自身が実行を行う場合の手順を示します。ハーネスは案件、ワークフロー、状態機械、予定日時を持たず、適用はその入力によって識別します。

使い方と安全策は[READMEのハーネスの節](../README.md#ハーネス)を、開発については[harness/README.md](../../../../harness/README.md)（英語）を参照してください。

## Pluginへの統合

Claude Codeは、`.mcp.json`からハーネスのMCPサーバーを、`commands/`から`/alps:harness`コマンドを登録します。根の`package.json`と`bun.lock`はハーネスの実行時の依存だけを持ち、Claude CodeがPluginの取得時にそれを導入します。開発用の道具は`harness/`にあり、その導入には含まれません。Codexは、根の`plugin.json`と、Agent Pluginsの`mcp.json`を読みます。`.codex-plugin/plugin.json`も`mcp.json`を指します。Cursorのアダプターは外しました。CursorはAgent Plugins形式を通じてSkillを読み込みますが、`${PLUGIN_ROOT}`を展開しないため、ハーネスのMCPサーバーは起動しません。

ハーネスには、クライアントの`PATH`にあるBun 1.3.11以上が必要です。macOSとLinuxに対応し、Windowsは試験的な対応です。設計のSkillにBunは不要です。

## 例とリポジトリ

[service-changeのワークスペース](../../../../examples/locales/ja/service-change/alps-harness.yaml)は、英語版と日本語版があり、架空の11のプロセスを15のアーティファクトの型でつなぎ、三つの例のSkill、合成データのアーティファクト、目覚めたエージェントのための運用の案内を含みます。その本番リリースのSkillには、プロセスモデルと同じく、候補版の変更により先の検査と承認の根拠が無効になることを記述しました。

検証のワークフローは、ハーネスの型検査、lint、整形の検査、テストをmacOSとLinuxで実行し、Windowsでは合格を必須とせずに実行します。リポジトリのテストは、MCPサーバーの登録、コマンド、実行時の依存だけを入れる取得時の導入、Hostアダプター、ハーネスの版を検査し、`mcp.json`をそのスキーマで検証します。`localization.yaml`は、ロケールのレビューのために、ハーネスの英日の辞書を列挙します。

## 0.8.0からの更新

Plugin全体を更新し、クライアントを再読み込みしてください。Plugin名`alps`、二つの設計Skill、それらのパスは変更していません。設計Skillはハーネスなしで機能します。Pluginには、`run-process` Skill、`harness` MCPサーバー、`/alps:harness`コマンドが加わります。Claude Codeではツールが`mcp__plugin_alps_harness__<ツール名>`として現れます。必要に応じて権限の規則を加えてください。`instantiate`、`run`、`cancel_run`、`finish_run`、`evaluate`、`wake`、`open_ui`は効果を持ちます。

ハーネスを使うにはBunを導入してください。Claude CodeがPluginの取得時にハーネスの依存を導入できなかった場合や、クライアントが依存を導入しない場合は、Pluginのディレクトリで`bun install`を実行してください。`.cursor-plugin/plugin.json`を読むツールは、代わりに根の`plugin.json`を読む必要があります。

以前の単独のハーネスのワークスペースは、ファイルをそのまま使えます。置き場所のパターンの`<case>`は`*`として読み、版のない`.alps-harness/state.json`は読み込み時に変換して、作業項目を案件なしのインスタンスにします。タイムライン、カンバン、予定日時はなくなりました。ワークスペースの無視の規則に`.alps-harness/`を加えてください。

ハーネス、そのMCPサーバー、根の依存のmanifestは、機械が解釈する形式とリポジトリのパス契約を追加するため、[バージョン方針](../versioning.md)に基づく1.0未満のMINORリリースです。再現性のため、移動するブランチではなく、公開された`v0.9.0`タグと、そのタグが指すコミットSHAを記録してください。詳しい変更は[CHANGELOG](../../../../CHANGELOG.md)に記載しています。

## 実物のエージェントでの検証

2026年9月30日、macOSで、service-changeの例を一時ディレクトリに写し、実物のCodex（ChatGPTのプランのcodex-cli 0.158.0。`model_reasoning_effort="medium"`とし、サンドボックスはワークスペースだけに書けるようにした）と実物のClaude Code（2.1.96。claude.aiのTeamプランでログインし、`claude-opus-4-6[1m]`を使った）でハーネスを動かしました。

- **Codexでのプロセスの実行。** CHG-002の要件の明確化（`docs/changes/CHG-002/stakeholders.md`から`docs/changes/CHG-002/change-brief.md`へ）は80秒で正常に終わり、変更の概要を書きました。一つのニーズと四つの受け入れ条件、解の選択への影響を添えた六つの曖昧さです。入力は96,428トークン（うち81,152はキャッシュ）、出力は1,729トークンでした。Codexは費用を報告しません。
- **その評価。** 変更の概要を二つの成果に照らして判断したのはエージェントで、この検証を行ったClaude Codeのセッションです（実行したエージェントではありません）。どちらも達成と判断し、限界を添えました。受け入れ条件はエージェントの提案で、関係者の承認を得ていないこと、曖昧さが重要なものを尽くしているかは関係者が要ることです。**人による評価はまだです。** 実行が正常に終わったことは証拠ではありません。
- **Codexでの目覚め。** 165秒で（入力458,691トークン、うち404,096はキャッシュ、出力4,163トークン）、目覚めたCodexはモデルと`docs/operations.md`を読み、ハーネスのMCPのツールを確認なしで14回呼びました（`default_tools_approval_mode = "approve"`）。案内が本番を先にするとおり、本番の観察に対してインシデント対応を、次にCHG-001の試行の測定を走らせ、どちらも自分で行いました。例には本番も試行の能力もないため、どちらも失敗で終わりました。その成果を判断し（多くは未確認）、なぜ作業ができなかったかと何が待っているかを、`finish_run`で状態を失敗として報告しました。二つの実行は目覚めの実行の`started`に並んでいます。
- **Claude Codeでのプロセスの実行。** 同じ関係者の情報からのCHG-002の要件の明確化（Codexが書いた概要は脇に移しました）は58秒、0.23ドルで正常に終わり、一つのニーズ、三つの受け入れ条件、解の選択への影響を添えた四つの曖昧さを持つ変更の概要を書きました。検証を行ったClaude Codeのセッションが二つの成果をどちらも達成と判断し、限界を添えました。受け入れ条件に境界がないこと、概要が対立に触れないこと、選んだ配達日時が約束か希望かなど、おそらく重要な曖昧さが抜けていることです。**人による評価はまだです。**
- **Claude Codeでの目覚め。** 目覚めたClaude CodeはハーネスのMCPサーバーにつながり、確認なしでツールを呼び、毎回`finish_run`で報告しました。1回目の目覚め（154秒、0.42ドル）は、偽のエージェントが作った解決案の設計を未達成と判断し、何も起動しませんでした。2回目（325秒、0.74ドル）は、新しい変更CHG-003の関係者の情報を置いた後で、CHG-003の要件の明確化（56秒、0.16ドル）とCHG-002の実現可能性の評価（139秒、0.36ドル）を起動し、四つの成果を達成と判断し、モデルへの要求を12回使いました。検証の設定が与えた`--max-turns 12`のちょうど上限です。二つの目覚めは、同じ概要について案内の「変更の概要が固まったら」を逆に読みました。1回目は開いた四つの曖昧さを固まっていない印とし、2回目は明確化が正常に終わったことを固まった印としました。これらの判断はエージェントのもので、ハーネスはそのまま残します。
- **見つかった問題と修正。** 2回目の目覚めが起動した二つの実行は同時に動き、実現可能性の評価の記録が、もう一方の実行が作ったCHG-003の概要を自分の出力とし、由来にも記録しました。ハーネスがインスタンス自身の置き場所ではなく、型の置き場所のパターン全体を比べていたためです。今は、具体的な置き場所の出力はそのパスだけです。エージェントがパターンの中で決めるときは、単独の実行ならそこでの変化がすべて出力です。同時に動く実行があるときは、そのどれかが具体的な置き場所として指すものはその実行の出力にせず、実行の入力がパターンのワイルドカードに与える値のディレクトリにある変化を優先します（入力`docs/changes/CHG-003/stakeholders.md`はCHG-003を与えます）。それでも同時に動いた実行がともに持つ変化は、それぞれの記録に印を付け（`sharedWith`）、所見が出所の分からないことを示します。アーティファクトの一覧と目覚めのプロンプトが示す由来は、そのうち最後に終わった一つの実行です。目覚めたClaude Codeはアカウントのclaude.aiのコネクターも読み込んでいました。今は`--strict-mcp-config`を付けて起動し、ハーネスのMCPサーバーだけを読み込ませます。ハーネスは自分の環境をまるごとエージェントに渡していたため、Claude Codeのセッションの中から起動したサーバーは、そのセッションの印（`CLAUDECODE`、`CLAUDE_CODE_ENTRYPOINT`、`CLAUDE_EFFORT`など）を受け渡していました。この検証では、それらを外してサーバーを起動しました。今はClaude Codeのエージェントがそれらを受け継がず、認証の情報、設定、`PATH`は残ります。
- **Claude Codeの出力の読み方。** GlobとGrepの呼び出しは、パターンとどこを探すかを示します。長い絶対パスは、ファイルの名前がある末尾を残します。MCPのツールの呼び出しは、引数ごとの名前と短い値を示します。セッションのMCPサーバーとそれぞれがつながったか、レート制限、セッション自身が述べる終わり方（止まった理由、かかった時間、権限が拒んだツールの使用）はイベントになり、拒まれたツールの使用は失敗の内容にも入ります。Claude Codeの`num_turns`はツールの往復の数に1を足したもので（2回目の目覚めでは23、上限は要求12回でした）、ハーネスはそのまま記録し、WebUIと`get_run`の説明にそう書きました。
- **採取した出力による変更。** 偽のエージェントは、Codexの出力（実行と失敗）とClaude Codeの出力（上の要件の明確化の実行と、ログインしていないときの失敗）を採取したとおりに出すようになりました。ハーネスは、`success`でありながら`is_error`を持つClaude Codeの結果を失敗として、その文から読み、モデルのAPIのエラーをJSONのまま運ぶCodexのエラーを、そのエラーのメッセージとして読みます。CodexのMCP呼び出しが失敗したときはそう示します。
- **使用量。** Claude Codeはトークン、費用、ターン数を、Codexはトークンだけを報告します。入力トークンを同じ数え方にしました。Codexと同じく、プロンプトのキャッシュから読んだ分と書いた分を含むすべてです（Claude Codeの`input_tokens`はキャッシュ以外の分だけを数えます）。実行の使用量に、キャッシュから読んだ入力トークン`cachedInputTokens`を加え、ダッシュボード、実行の表示、所見と統計が示します。
- **MCPサーバーの作業ディレクトリ。** Codexは、設定が`cwd`なしで挙げるMCPサーバーを自分の作業ディレクトリ、つまりプロジェクトで起動し、ハーネスはワークスペースを見つけます。`cwd`を省いたときにAgent Pluginsが求めるとおりPluginの根で起動すると、ハーネスは`no-model`を返します。そのメッセージは、`ALPS_WORKSPACE`にプロジェクトのディレクトリを渡すか、そのディレクトリでハーネスを起動するよう案内するようにしました。CodexのMCPクライアントは`roots`を宣言しません。Claude Code 2.1.96はPluginのMCPサーバーをプロジェクトのディレクトリで起動しますが、`ALPS_WORKSPACE`を展開していない`${CLAUDE_PROJECT_DIR}`のまま渡します。ハーネスは、`${…}`を含んだままで、実在するパスを指さない値を無視するようにしました。
- **Claude Code 2.1.96でのPlugin。** `claude plugin validate`は、`.claude-plugin/plugin.json`の`$schema`と`displayName`を未知の鍵として報告し、0以外の終了コードで終わります。2.1.96がこれらより前の版だからで、Pluginはこれらを含んだまま読み込まれます。`--plugin-dir`では、Pluginがそのセッションだけ導入済みのものに代わり、そのMCPサーバー`plugin:alps:harness`はワークスペースを見つけました。きれいなcloneをローカルのマーケットプレイスから導入すると（別の設定ディレクトリで`claude plugin marketplace add`と`claude plugin install`）、Pluginは5秒で写されましたが、依存は導入されませんでした。

エージェントの費用：Claude Codeは、それ自身の報告で合わせて1.92ドルです（要件の明確化の実行0.23ドル、目覚め0.42ドルと0.74ドル、2回目の目覚めが起動した二つの実行0.16ドルと0.36ドル）。Codexは、MCPサーバーの作業ディレクトリの二つの確認を含めて、合わせて入力663,509トークン（うち551,552はキャッシュ）と出力6,255トークンで、費用を報告しないChatGPTのプランの上です。

## 未検証の事項

ハーネスのE2Eテストは、コマンドライン、HTTP API、MCPサーバー、WebUIを、偽のエージェントとともに本物のプロセスとして動かします。これが示すのは部品と接続の振る舞いと安全策の検査であり、プロセスの成果が達成されることではありません。執筆時点で次は未検証です。

- 上の実行の成果を人が評価すること。これまでの判断はどれもエージェントのものです。
- 実物のClaude Codeで、`error_max_turns`で終わる実行、ツールの使用が拒まれる実行、結果が来ない実行の使用量。実行の後に行い、偽のエージェントで確かめた上の修正（同時に動く実行の出力、`--strict-mcp-config`、エージェントが受け継ぐ環境）。Pluginを導入した環境で、目覚めたClaude CodeがPlugin自身のハーネスのサーバーも読み込むか。
- 現在のClaude Codeが、GitHubのマーケットプレイスからこのPluginを取得するときに依存の導入を実行するか、それが60秒の上限に収まるか。デスクトップのアプリケーションから起動したClaude Codeが`PATH`の`bun`を見つけるか。
- Pluginを導入したCodexについて（導入は利用者のCodexの設定を変えるため、試していません）。MCPサーバーをプロジェクトのディレクトリで起動するか、ハーネスがワークスペースを見つけられないPluginの根で起動するか。依存を導入するか。`mcp.json`と`.codex-plugin/plugin.json`の`mcpServers`がサーバーを一度だけ登録するか。
- 目覚めたCodexが`get_run`で最大300秒待つこと。ハーネスはMCPサーバーに330秒の`tool_timeout_sec`（Codexの既定は60秒）を与えるようにしましたが、上の目覚めはその前に行ったものです。
- `claude plugin validate`によるMCPサーバーの項目の検査は、まだ実行していません。検証のワークフローはこれをClaude Code 2.1.285で実行します（この検査には2.1.281以上が必要です）。
- Windowsで、エージェントのプロセスツリー全体の停止と、テスト全体。
- このリポジトリ自体をClaude Codeで開くと、根の`.mcp.json`がプロジェクトのMCP設定としても読まれ、そこでは`${CLAUDE_PLUGIN_ROOT}`が設定されていません。リポジトリの開発と、例のワークスペースでの実物のエージェントの実行への影響は調べていません。
- テスト全体の実行で、E10が操作するブラウザがときどき応答しなくなることがあり、原因は特定していません。
