# ALPS 0.7.0

[Japanese translation](../locales/ja/releases/0.7.0.md)

ALPS 0.7.0 supports designing both the meaning of work and the agent work system that realizes it.

## Design responsibilities

- [design-process-description](../../skills/design-process-description/SKILL.md) clarifies work meaning, observable Outcomes, necessary Activities and Tasks, boundaries, and applicable conditions.
- [design-agent-work-system](../../skills/design-agent-work-system/SKILL.md) designs the agents, tools, information resources, execution environment, and interactions that support the work. It includes implementation, connection, and verification within the request.

The Skills have distinct design and evaluation subjects. They can be used independently when the necessary basis is available, and both refer to the same source of target work meaning.

## Specifications and example

[Design Principles for Agent Work Systems](../../spec/agent-work-system-design.md) defines responsibility allocation, tool interfaces and composition, information supply, execution conditions, evaluation, and adaptation to changed capabilities. It is independent of the [Process Framework](../../spec/process-framework.md), whose English and Japanese texts are unchanged from 0.6.0. The [ALPS Specification](../../spec/ALPS-SPEC.md) integrates the two foundations in Agent Skills.

The [service-change example](../../examples/README.md) contains a target Skill, a Python measurement tool, synthetic inputs, applicable criteria, and evaluation cases. It shows how an agent interprets evidence while a tool performs established validation, calculation, and comparison. The example is bundled reference material outside Plugin Skill discovery.

The Specification defines separate Purpose and Outcomes sections, a recommended Activity and Task layout, and the representation and informative role of NOTEs. Both design Skills apply this writing structure. Tool correspondence also identifies implemented Controls and enforced Constraints alongside enabling capability, distinguishing configuration limits from work requirements.

Evaluation distinguishes description validity, tool and connection behavior, and effectiveness through representative work. English/Japanese assets, discovery links, native Host manifests, repository tests, and validation guidance cover the two design Skills.

## Updating from 0.6.0

Update the complete Plugin and reload the client. Preserve `spec/` and `examples/` along with `skills/`, so specifications and example resources remain available. The discovered Plugin Skills are `design-process-description` and `design-agent-work-system`.

The existing Process Description Skill path and its central responsibility remain. The added normative content and distribution structure make this a MINOR release under the [version policy](../versioning.md). Consumers maintaining their own file allowlists or discovery lists need to include the new Skill and supporting files. Work-system design under this version uses the integrated specification and its evaluation requirements. Existing user descriptions and data are not converted by this update.
