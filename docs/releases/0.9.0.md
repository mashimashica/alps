# ALPS 0.9.0

[Japanese translation](../locales/ja/releases/0.9.0.md)

ALPS 0.9.0 adds `create-process-models` for creating a process model as one Agent Plugin, with explicit model membership, display titles, typed I/O, and shared definitions. The release also corrects numeric boundary comparisons in the service-assessment example.

## Process model creation

[create-process-models](../../skills/create-process-models/SKILL.md) organizes related work into coherent Process responsibilities, observable success conditions, and shared information relationships. It creates the canonical package files and verifies their consistency within the request. Its guidance and references are self-contained; it can be used independently of the two existing design Skills.

The Plugin now distributes three Skills: `design-process-description`, `design-agent-work-system`, and `create-process-models`. English and Japanese guidance, repository discovery, validation, and Codex presentation include the new Skill. Both READMEs explain when to use it, what to supply, and which files it produces.

## One model, one Plugin

The [model format](../../skills/create-process-models/references/model-format.md) introduces ALPS model profile version 1:

- `plugin.json` explicitly lists model members in its ALPS extension. Helper Skills are not members merely because a Host discovers them.
- Each listed process Markdown document owns its complete description, stable identifier, display title, and I/O declarations. Agent Skills use `skills/<name>/SKILL.md`; other work, including human work, can use ordinary Markdown.
- `references/artifacts/<id>.md` defines each shared information item, product, or service referenced by I/O. Concrete artifact paths and execution settings remain optional workspace configuration.

Every registered process document requires a nonblank string `metadata.title`, in its document's language. The stable identifier and H1 do not substitute for this display title. This requirement does not extend to unregistered helper Skills or artifact definitions. Declared `metadata.inputs` and `metadata.outputs` are JSON arrays of type identifiers encoded as strings.

A graph is a projection of these sources. The profile introduces no separate model file, type registry, or copied Purpose and Outcomes. It allows cycles, and I/O relationships do not prescribe execution order or establish approval, readiness, or success. Criteria, policies, and requirements retain their governing meaning and applicability as Controls in the source descriptions; the format has no separate Controls metadata field or edge category. Model-authoring guidance remains separate from an application's display, execution, and evaluation implementation.

## Example and documentation corrections

The [service-assessment example](../../examples/README.md) compares decimal duration limits and error-count ratios exactly, preventing rounding from changing an inclusive boundary judgment. Reported JSON numbers may still be rounded; Boolean checks are calculated before that conversion. The tool guidance explains this distinction, and regression cases cover the comparisons. The Python requirement remains 3.10 or later.

README release-note references are checked against `VERSION`. Translation manifests track the reviewed English sources, including this release's Japanese notes.

## Updating from 0.8.0

Update the complete Plugin and reload the client. Confirm that all three Skills are discoverable and their references open. The Plugin name `alps` and the two existing Skill identifiers and paths are unchanged. Keep each Skill's full directory when distributing it individually.

When adopting the model profile, check explicit manifest membership, each process's `metadata.title`, string-encoded I/O arrays, and the corresponding shared definitions. Converting an existing model requires explicit changes to its canonical sources and affected references; the profile defines no fallback to an old model format. A successful package check does not demonstrate successful execution of the modeled work.

The new Skill and machine-consumed model profile make this a pre-1.0 MINOR release under the [version policy](../versioning.md). Profile version `1` is distinct from the ALPS release version `0.9.0` and from each created model Plugin's own release version.

After publication, record the `v0.9.0` tag and its resolved commit SHA for reproducibility. Detailed changes are in the [changelog](../../CHANGELOG.md).
