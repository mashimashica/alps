# ALPS 0.4.0

ALPS 0.4.0 adds a Markdown Repository and Agent Plugins Binding for Process Models and Process Views. It standardizes default and named Model entry points, View assets, compatibility declarations, local and external Skill source resolution, and mechanical preflight while retaining the three ALPS Reference Skill identifiers.

## Model and View binding

The binding identifier is:

```text
alps-markdown-agent-plugins/1.0
```

Canonical locations are:

```text
.alps/MODEL.md
.alps/models/<model-id>/MODEL.md
.alps/views/<view-id>/VIEW.md
```

The full binding is documented in [markdown-agent-plugins.md](../../.alps/bindings/markdown-agent-plugins.md). English and Japanese templates are provided under `.alps/templates/`.

## ALPS Reference Model

The package now contains [`.alps/MODEL.md`](../../.alps/MODEL.md), which describes the relationships among `define-alps`, `apply-alps`, and `manage-alps`. It is a Model asset, not an independently invokable Skill, and it does not impose a fixed life-cycle sequence.

## Mechanical preflight

- `scripts/check_model_view.py` validates binding structure.
- `scripts/resolve_model_view.py` discovers assets, evaluates ALPS compatibility, resolves local Skill sources, and can resolve installed external plugin roots.

These tools provide mechanical preflight only. They do not establish semantic adequacy, Outcome achievement, suitability, adoption, or Execution Conformance.

## Reference Skill changes

- `define-alps` now covers Model and View need identification, design, and verification.
- `apply-alps` now resolves a default or selected Model, applies compatible Views, and preserves source and handoff identity.
- `manage-alps` now governs Model and View adoption, compatibility, change, release, and retirement.

## Compatibility

The binding introduced by this release uses the ALPS compatibility range:

```text
>=0.4.0 <0.5.0
```

Existing Skill identifiers and root `skills/` paths remain unchanged. Packages that do not contain Models or Views remain valid ALPS Skill packages. Clients that do not understand the namespaced Agent Plugins extension may ignore it.

ALPS remains in initial development. The tag and public release are created only after the release candidate is reviewed and merged.
