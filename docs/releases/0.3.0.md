# ALPS 0.3.0

ALPS 0.3.0 adds cross-platform plugin discovery and presentation metadata, improves the adoption documentation, and aligns the Japanese localization. The root Agent Plugins package layout and the three ALPS Reference Model Skill identifiers remain stable from 0.2.0.

## Client-specific plugin metadata

The root [`plugin.json`](../../plugin.json) remains the portable Agent Plugins 1.0 manifest. This release supplements it with client-specific metadata:

| Client or binding | Metadata |
| --- | --- |
| Claude Code | [`.claude-plugin/plugin.json`](../../.claude-plugin/plugin.json) |
| Codex | [`.codex-plugin/plugin.json`](../../.codex-plugin/plugin.json), per-Skill `agents/openai.yaml`, and bundled Skill icon assets |
| Cursor | [`.cursor-plugin/plugin.json`](../../.cursor-plugin/plugin.json) |

The three Skill Packages now include client-facing interface metadata and local copies of the ALPS icon where the consuming client expects package-relative assets.

## Documentation and localization

The English and Japanese READMEs now lead with installation, reference Skill selection, explicit invocation, and reusable repository guidance before presenting the Process Framework in more detail.

Installation guidance has been simplified around:

```console
npx plugins add mashimashica/alps
```

Japanese Process Description prose and terminology have been clarified and aligned with the authoritative English sources, including adaptation-related wording. These localization changes do not alter the authoritative English Process Framework, ALPS Specification, or reference Skill semantics.

## Compatibility status

The `define-alps`, `apply-alps`, and `manage-alps` identifiers and the root `skills/` paths introduced in 0.2.0 are unchanged. Consumers already using those identifiers and paths do not need to rename them.

ALPS remains in initial development. This release adds machine-consumed client manifests and interface metadata, so it is a MINOR release under the pre-1.0 versioning rules. The exact release contents are identified by the `v0.3.0` tag and the commit to which that tag points; pin both the tag and commit SHA when synchronizing ALPS assets.
