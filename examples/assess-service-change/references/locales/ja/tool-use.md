# 測定ツール

[英語版](../../tool-use.md)

[スクリプト](../../../scripts/compare_measurements.py)は、二つのローカルCSVスナップショットを読み込み、検証し、リクエスト指標を計算し、指定された数値限度と比較する。依存関係はPython 3.10以降とその標準ライブラリだけである。例のSkillディレクトリから呼び出すか、スクリプトと入力ファイルに絶対パスを用いる。

```console
python3 scripts/compare_measurements.py assets/baseline.csv assets/candidate.csv --min-samples 4 --max-p95-ms 200 --max-error-rate 0.05 --max-p95-increase-ms 50
```

引数のインターフェースは`--help`で確認する。適用する[試行条件](pilot-context.md)から限度値を選ぶ。呼出し側が、比較にどの基準を適用したか識別できるよう、ツールは限度値の明示指定を必要とする。

両ファイルはバイト順マークのないUTF-8のCSVとし、厳密に`request_id,duration_ms,status`の順のヘッダー、1行以上のデータ、各ファイル内で一意かつ空でなく前後に空白を持たないリクエスト識別子、非負の十進数（`100`や`12.5`のように、数字と任意の小数部）で書かれたミリ秒単位の応答時間、`ok`または`error`の`status`を持たなければならない。ツールは両ファイルが同じリクエスト識別子の集合を持つかを報告する。それらの識別子が同一の固定リクエスト群を表すかは、測定文脈からの判断として残る。不正または不完全な行は拒否する。最小件数は正の整数でなければならず、その他の限度値は応答時間と同じ十進数の形式で書かなければならず、エラー比率は0から1でなければならない。

標準出力は一つのJSONオブジェクトであり、指定された限度値、各ファイルのパスと読み込んだバイト列のSHA-256ダイジェスト、件数、エラー比率、nearest-rank法のp95、`input_relationship`オブジェクト、p95の差、各数値比較の真偽値を含む。`input_relationship`では、`identical_bytes`が二つのダイジェストの一致を、`same_request_ids`が両ファイルのリクエスト識別子の集合の一致を報告する。これはこの例のツールのインターフェースである。指定された最小件数未満のデータも有効な入力であるが、件数の検査は不合格になる。終了コード`0`は、一つ以上の限度を満たさない場合も含め、計算が完了したことを意味する。試行基準が確認されたことは意味しない。終了コード`2`は、不正な引数、不正な測定、読込み不能なファイルを標準エラーへ報告し、結果オブジェクトを出力しない。

この操作はファイルを読み込み、標準出力と標準エラーだけに書き込む。入力の変更、サービスの配備、ネットワークサービスの呼出しは行わない。各ファイルは一度読み込み、そのスナップショットをダイジェストで識別する。測定が同時更新される可能性がある場合は、安定したコピーを用いる。同じバイト列と限度値で繰り返せば、同じ指標と検査結果を得るが、応答のパスは異なる場合がある。読込みや検証に失敗した場合は、示された入力またはアクセスの問題を修正してから再試行する。

エージェントは、数値検査を測定文脈、適用基準、仕事の成果へ対応付けなければならない。JSONを正常に生成できても、比較可能性、測定の出所の真実性、指定された試行を超える適合性は確認できない。
