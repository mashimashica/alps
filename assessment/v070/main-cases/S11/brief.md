# Revise Meridian's customer-care work descriptions

Meridian Field Instruments maintains one shared customer-care policy and several short descriptions of the work that depends on it. The operations owner has authorized a change to the Launch Assist eligibility criterion and the source used to establish its start date. The existing descriptions were written for the old criterion, while other care rules happen to use a similar number of days for different purposes.

Create a reusable Agent Skill for making a scoped revision across a related set of business work descriptions after an authorized source or criterion change. Then apply it to this supplied document set as of 2026-07-21. Produce an updated, usable local document bundle and enough change explanation for a later maintainer to see what changed, why, and what was deliberately preserved. Choose a form that suits the work; no particular report layout or automation is required.

The authoritative change is `sources/approved_change.md`. It identifies the shared policy, its precise scope, and the new source interface. The baseline policy is in `sources/policy/`; the descriptions that use it are in `sources/work/`. The commissioning register interface is in `sources/interfaces/`. These are fictional internal documents, not an invitation to find a different policy online.

The revised bundle must keep MFI-CARE-07 as the common maintained policy source. The team cannot support separate local copies of the eligibility rule embedded in each work description. A person following any affected description should reach a consistent current criterion and have the information needed to carry out that work. Related but unaffected work must retain its meaning, including independently defined delivery-based time windows. Do not treat every occurrence of “14 days” or “delivery” as the same dependency.

You may read the supplied packet and create the Skill, a revised working bundle, and any useful local support files under a new `deliverables/` directory. Keep the supplied `sources/` baseline unchanged and make links within the revised bundle usable. Do not edit the commissioning register, decide live customer cases, recalculate closed cases, notify customers or staff, or publish policy changes externally. This authorization is for the approved document revision only. If the packet does not authorize a substantive change, preserve that meaning and identify any unresolved issue instead of supplying a new rule yourself.
