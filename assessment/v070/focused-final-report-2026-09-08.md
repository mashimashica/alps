# ALPS v0.7.0 — 固定比較の実測結果

今回の比較では、ALPS による依頼対応率の向上や、利用時の修正負担の減少は確認できませんでした。一方、生成された Skill の成功条件・不確実性の扱いには改善対象が見つかりました。**同条件での大量反復を追加する段階には進まず、具体的な意味の欠陥を少数の反例で検証することを推奨します。** 効果がないことや、リリース可能であることを証明した結果ではありません。

## 完了した範囲

[事前に固定した計画](focused-comparison-plan.md)の追加44試行を完了しました。内訳は ALPS ありの12生成・24適用と、未実施だった ALPS なしの8適用です。既存の12生成・16適用を再利用し、比較対象は**24個の Skill・48適用**です。不利な生成物の差し替えや追加生成は行っていません。

対象は引継ぎ、台帳集計、リリースの3業務、それぞれ通常・難例の2ケースです。各業務・各条件で、sol/high と astra/high が2回ずつ生成し、別の新規コンテキストの sol/high が各 Skill を2ケースへ適用しました。両条件とも同じ固定版 skill-creator を任意に利用可能としています。ALPS の記録上の使用と、共通補助 Skill の実際の使用は各意味レビューに記載しています。

6つの匿名化資料に各2人の独立した業務レビューを行い、ALPS 側には業務ごとの3件の意味レビューを追加しました。**12件の業務レビュー＋3件の意味レビューが完了**しています。1件の指摘の再確認は同じレビューの補足であり、16件目の独立レビューとして数えていません。

## 依頼への対応と修正

「適切」は、可能な依頼作業を行い、条件・証拠・未完了を正しく扱えたことです。業務の全 Outcome が達成されたこととは別です。率は各生成 Skill の2適用の評価を等重みで集計しています。

| 業務 | ALPS なし | ALPS あり | あり−なし | Skill 由来の修正：なし／あり |
| --- | ---: | ---: | ---: | ---: |
| 引継ぎ | 8/8（100%） | 7/8（87.5%） | −12.5ポイント | 0／0 |
| 台帳集計 | 8/8（100%） | 8/8（100%） | 0ポイント | 0／0 |
| リリース | 8/8（100%） | 8/8（100%） | 0ポイント | 0／0 |
| 合計 | 24/24（100%） | 23/24（95.8%） | −4.2ポイント | 0／0 |

ALPS 側の1件は、最終メッセージで「ラベルを受け取る期限」を「貼り付ける期限」に変えた、利用側の軽微な誤りです。保存された回答本文と生成 Skill はその点で正しく、重大な適用失敗は両条件とも0件でした。**共通に保存されている回答本文だけで評価すると、両条件とも24/24です。** 過去の対照条件の引継ぎ・台帳16適用には別の最終メッセージが残っていないため、上の差を ALPS の悪影響とは解釈できません。[判定根拠](grades/focused-FP02-adjudication.md)

修正件数は、誤った Skill 指示・処理を利用側が実際に補った証拠の件数です。通常の判断、指定された失敗からの復旧、利用者自身の補助コマンドのミス修正は含めません。**0件は未記録の労力までゼロという意味ではありません。** 全48適用を残して判定し、記録が不完全な対照適用も、その限界を付したまま評価しています。

| 作成モデル・エフォート | ALPS なし：適切な適用 | ALPS あり：適切な適用 | ALPS 側の重要な意味上の欠陥 |
| --- | ---: | ---: | ---: |
| gpt-5.6-sol / high | 12/12 | 12/12 | 3/6 Skill |
| gpt-6-astra / high | 12/12 | 11/12 | 0/6 Skill |

この少数結果からモデルの一般的優劣は判断しません。適用側は全て sol/high です。

## 業務の Outcome

各条件8適用あたり、両条件とも次の結果でした。

| 業務 | 通常4件 | 難例4件 |
| --- | --- | --- |
| 引継ぎ | 元の会話で合意を確認済み。回答が新たに合意を成立させたわけではない | 合意は部分的。未確認の担当・承認等を明示し、有用な次の発話を提示 |
| 台帳集計 | 全6レコードを確認し、正確な完全集計 | 許可された6/15レコードで中断。継続位置と部分結果を保存し、完全集計とはしない |
| リリース | 指定された承認済みリビジョン、稼働確認、checkout が成立 | 一度だけ反映された変更を応答喪失後に確認。checkout 失敗を検出し、リリース成功とはしない |

台帳は実働する生成スクリプトを使い、リリースは提供された既存 CLI を使いました。リリース結果はファイル内のシミュレーションであり、本番システムの結果ではありません。

## 生成 Skill 自体から分かったこと

適用結果だけでは、記述の評価上の欠陥を検出しきれません。ALPS 側の意味レビューで、次の**3/12 Skill に重要な欠陥**を採用しました。この追加の PF 忠実性レビューは ALPS 側のみなので、対照との欠陥率比較には使いません。

| 生成物 | 採用した問題 | 必要な改善 |
| --- | --- | --- |
| focus-001・002：引継ぎ | 未解決事項を正確に整理すれば、参加者間の理解が成立しなくても全 Outcomes と Exit Criteria を満たせる | 参加者の証拠による共有理解を成功条件として残し、有用な途中結果と区別する |
| focus-010：リリース | Outcome が「未確認」でも「達成されなかった」と断定する指示 | 確認不足と、確認された未達成を分ける |

原文と再判定は[引継ぎ](grades/focused-S03-fidelity-adjudication.md)・[リリース](grades/focused-S10-fidelity-adjudication.md)を参照してください。ALPS の原則には既にこれらの区別があり、生成物の欠陥を ALPS 原則そのものの誤りとは帰属していません。

台帳には、応答欠落時の終了コードと復旧説明のずれ、実行環境の依存条件、Input／Enabler の分類、独立に評価できる結果を同じ Outcome にまとめた箇所などの限定的な改善点がありました。完全集計の意味や、実施された集計が壊れたという結果ではありません。[台帳の意味レビュー判定](grades/focused-S06-fidelity-adjudication.md)

リリースの並行実行・処理中再試行に関する指摘は、[再確認](grades/focused-S10-fidelity-clarification.md)で重大な欠陥から除外しました。与えられた同期 CLI の保証と、別の実行条件での限界を混同しないためです。見出しの違いや追加スクリプトの不在も、それだけでは不良と扱っていません。

これは3業務を意図的に選んだ小規模比較です。各 Skill の2適用は同じ生成物を共有し、独立した生成試行ではありません。対照条件は先に収集され、一部は保存済みの公開テキスト・状態証拠から復旧されています。下位モデル実装の同一性、完全な操作履歴、欠けた過去のメタデータは確認できません。ALPS 側で多くの記録が残る観測差もあります。優位性・同等性の統計的証明には使いません。

台帳の意味レビュアーは指定一覧外の作成用プロンプトも読んだと報告しており、[範囲逸脱として記録](audits/focused-review-scope-observation.md)しました。追加で読まれたものは作成条件であり、適用ケース・正解・他の採点ではありません。主な指摘は実物の記述・コードを別途照合しました。読み取り制限は手続き上の指示であり、完全に強制された隔離ではありません。

作成者の追加テスト報告を、レビュアーが再実行したテストとしては数えていません。一般的な障害復旧、並行実行、大規模データ、Host 上での発見・動作、日本語での適用、未検証業務への転用は、この比較では確認していません。実測トークン数・費用を取得していないため、費用削減率も出していません。

## 次の投資判断

**同じケース・同じ強い設定で反復数だけを増やすことは推奨しません。** 対照条件が既に高い結果を出しており、今回の2指標では改善の余地を測りにくい状態です。

次に進むなら、成功条件の弱まりと未確認／未達成の混同を対象に、生成物のレビュー・改訂で欠陥が実際に減るかを見る小規模な評価を優先します。PF の意味、二つの Skill の設計対象、通常リンク、既存実行環境の利用という責務は維持します。原則や基盤を増やす変更の根拠は、今回の結果からは得られていません。

この報告で[44試行の固定比較](focused-comparison-plan.md)を完了します。ALPS 本体、VERSION、example の変更、新しい製品 PR、merge、tag、Release は行っていません。最高品質 example の選定・置換 PR と、広いリリース判断のための未実施段階は保留のままです。今回の完了を、それらの完了や承認として扱いません。
