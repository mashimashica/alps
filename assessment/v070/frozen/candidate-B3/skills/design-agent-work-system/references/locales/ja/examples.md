# 設計の問いと具体例

[英語版](../../examples.md)

本資料は[エージェント作業システムの設計](SKILL.md)のための参考情報である。依頼された設計に必要な詳細を選ぶ。構成は対象Skillと既存の資源に記述でき、以下の問いは別文書の作成を要求しない。

## 記述を始める

対象の仕事にAgent Skillの記述が必要な場合は、[プロセスの最小テンプレート](../../../../design-process-description/references/locales/ja/SKILL-template.md)を用いる。実現を支える設計では、その記述を参照し、必要な責務と相互作用を説明する。構成の利用・実現・評価に必要な詳細だけを加える。

有用な問いには、次がある。仕事と条件はどの参照元に記述されているか。各責務をどの能力が担うか。文脈に応じた判断はどこに必要か。各インターフェースをどの情報が通るか。仕事の結果をどの証拠が支えるか。何が未確認か。

## 既存ツールと新しい組合せ

リポジトリ保守では、既存の検索ツールが候補ファイルを探し、既存のコンパイラが変更を検査する。エージェントは依頼された動作を解釈し、対象コードを選ぶ。生成ファイルに対する既定の一連の検査は、既存の一つのビルドコマンドで公開できる。内部の検査は個別に保守でき、エージェントはその操作を適用する場面を選ぶ。ビルドコマンドが必要な動作と診断を提供するなら、追加スクリプトは不要である。

## 同梱する処理ツール

[サービス変更の例](../../../../../examples/locales/ja/README.md)では、CSVの検証、測定値の集計、閾値との比較を行うスクリプトを持つ対象Skillを用いる。これらの計算を一つの公開操作とする。エージェントは、適用する測定の組と基準を選び、比較可能性を評価し、証拠を解釈し、追加測定の必要性を判断する。目的と成果は例の参照元となる記述に保持し、実現を支える設計ではそれらを参照する。

## 能力・基準・制限

同じ測定操作が、[サービス評価](../../../../../examples/assess-service-change/references/locales/ja/SKILL.md)に対して複数の関係を持つ。

| 側面 | 仕事での役割 | 設計と評価への関係 |
| --- | --- | --- |
| 測定値の読取り、指標の計算、値の比較 | スクリプトが実行支援要素となる。 | 能力が定められた動作を実現しているか確認する。 |
| 試行の指標定義と受入限度値 | これらが統制事項となり、スクリプトがその計算と比較を実装する。 | 実装した基準を、適用する[試行条件](../../../../../examples/assess-service-change/references/locales/ja/pilot-context.md)へ対応付ける。 |
| 必須のCSV文字コードと列 | このツールのインターフェース利用を制限する。 | 利用可能な情報を、その意味を変えずにインターフェースへ供給できるか確認する。 |
| 返された測定値と比較結果 | 評価の証拠となる。 | 測定文脈と適用基準を合わせて解釈する。 |

ツールの能力と、基準の実装は、異なる関係である。規則は、その意味と適用範囲を識別できれば、設定やコードで表現できる。試行の例では受入限度値を明示的に渡す。基準を固定したツールでは、その基準の根拠と適用可能性を識別する必要がある。閾値の変更は判断基準に影響し、受け入れる情報と動作を変えないCSV解析の変更は、実装の変更になり得る。

利用できるAPIが1ページにつき最大1,000件を返す場合、その上限は呼出しに適用される。全件を評価する仕事の要求には、ページ取得の反復や他の十分な能力を用い、全件を対象とする必要がある。最初のページの証拠が裏付けるのは、そのページの結果に限られる。上限があることから、残りの記録が評価対象外とは判断できない。

## 状態を変更するツール

カレンダーAPIは、その保証が仕事の要求を満たす場合、予定の競合検出と作成を一つの操作にまとめられる。その場合も、誰がどの予定を作成できるか、どの状態が変わり得るか、同時変更が結果へどう影響するかを定める必要がある。作成が行われた可能性のある要求がタイムアウトした場合、対応する要求識別子と状態照会によって、再試行前に影響を確認できる。そうした能力が利用できない場合、状態を確認するまで結果は不確かであり、エージェントはタイムアウトから「何も起きなかった」と推測してはならない。

## 能力の変化

モデル更新後の設計レビューで、ツール選定の弱さを補う指示が不要と分かる場合がある。影響する仕事で、より簡潔な相互作用を評価する。どの記録を変更してよいかを定める業務基準と、実際の影響の証拠は維持する。プロンプトが短いことや呼出し回数が少ないことだけでは、改善は確認できない。
