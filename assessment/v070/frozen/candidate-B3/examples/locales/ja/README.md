# 実働例：サービス変更の評価

[英語版](../../README.md)

この参考例は、実働スクリプトを含む対象Skill一式である。Pluginが発見する`skills/`の外にある`examples/`へ参考資料として同梱する。仕事の名称、目的、成果、条件は[サービス変更の評価](../../assess-service-change/references/locales/ja/SKILL.md)を参照する。その記述を、以下の二つの設計責務に共通する参照元とする。

## 同じ仕事に対する二つの設計責務

| 責務 | この例で明確にする内容 | 評価対象 |
| --- | --- | --- |
| [プロセス記述の設計](../../../skills/design-process-description/references/locales/ja/SKILL.md) | 観察可能な評価結果、配備との境界、適用する試行基準、必要な活動とタスク、測定と能力の役割。 | [対象の記述](../../assess-service-change/references/locales/ja/SKILL.md)の意味と関係。 |
| [エージェント作業システムの設計](../../../skills/design-agent-work-system/references/locales/ja/SKILL.md) | エージェント、ローカルPythonツール、測定、試行文脈の相互作用と、計算に委ねる仕事、文脈判断が必要な仕事。 | 実現を支える構成、その実装、有効な評価の証拠。 |

## 構成とインターフェース

| 構成要素 | 責務と相互作用 |
| --- | --- |
| エージェント | 仕事の記述と適用文脈を識別し、測定と限度値を選び、計算を呼び出し、比較可能性を評価し、判断を正当化するか証拠不足を識別する。依頼範囲内で、追加測定や方法の変更を提案できる。 |
| [測定ツール](../../assess-service-change/scripts/compare_measurements.py) | CSV検証、集計、数値比較の確定した順序を、一つの公開操作として処理する。内部関数では入力検証とCLIの調整を分離する。 |
| 測定ファイル | 仕事で調べる入力。そのパスはツールの引数となり、内容と出所が証拠となる。応答は、用いたバイト列をSHA-256ダイジェストで識別する。 |
| [試行条件](../../assess-service-change/references/locales/ja/pilot-context.md) | 適用基準の統制事項であり、測定の比較可能性を調べる入力でもある。それぞれの役割を区別する。数値限度は明示的なツール引数となる。 |
| ローカル環境 | ファイル読込みとコマンド実行が可能なエージェント、Python 3.11以降、安定した読込み可能なファイル。スクリプトはネットワークや第三者パッケージを必要としない。 |

スクリプトは評価で利用する際は実行支援要素であり、この構成を実装する仕事では出力である。一度の呼出しが計算と解釈のタスクを支えるが、それらのタスクが評価するすべての条件を確認することはできない。JSONの戻り値はエージェントが用いる計算の証拠であり、評価の結果は測定文脈にも依存する。エージェントは依頼された媒体で判断を提示でき、固定の報告ファイルは必要ない。

## 処理操作の実行

`examples/assess-service-change/`から次を実行する。

```console
python3 scripts/compare_measurements.py assets/baseline.csv assets/candidate.csv --min-samples 4 --max-p95-ms 200 --max-error-rate 0.05 --max-p95-increase-ms 50
```

データの意味、依存関係、呼出し方、失敗への対応、再現性の条件は、[ツールの利用方法](../../assess-service-change/references/locales/ja/tool-use.md)を参照する。同梱したデータでは、基準p95は**130 ms**、候補p95は**160 ms**、増加は**30 ms**、候補エラー比率は**0**となり、すべての数値比較を満たす。肯定的な試行評価には、[指定された文脈](../../assess-service-change/references/locales/ja/pilot-context.md)が適用されることも必要である。

## 評価ケース

次の表は、この例の評価基準であり、あらゆるエージェントや環境を検証済みと主張するものではない。

| 層 | ケースと証拠 | 必要な解釈 |
| --- | --- | --- |
| 記述 | フレームワーク、試行条件、システム設計に照らして対象の記述をレビューする。 | 評価、配備、数値結果、各成果に必要な証拠が区別されている。 |
| ツールと接続 | 同梱した組に記載どおりのCLIを実行し、戻り値を解析し、確認可能なデータから指標を照合する。 | 値と比較が計算仕様に一致し、入力を追跡でき、エージェントの既存コマンドツールから利用できる。 |
| ツールの失敗 | ファイル不足、不正な行、重複識別子、不正なstatus、非有限の応答時間を与える。 | 終了`2`と診断を返し、結果オブジェクトを出さない。依存する評価の前に有効な証拠を得る。 |
| 作業システム | 同梱した組と、その適用可能な文脈を用いる。 | この合成データによる試行だけに肯定的な判断が裏付けられ、小さな標本と本番への限界が示される。 |
| 作業システム | 候補のコピーの最終リクエストを`c4,2000,error`へ変え、このテストケースでは指定された測定文脈を維持する。 | ツールは終了`0`のままだが、候補p95は2000 ms、エラー比率は0.25、p95増加は1870 msとなる。エージェントは否定的な試行評価をしなければならない。計算の完了で候補が許容可能になったわけではない。 |
| 作業システム | 通常の測定値を与えるが、候補では同時クライアント数が1でなく10だったと明示する。 | 数値検査は満たしたままだが、比較可能な条件は確認できていない。影響する評価の成果は未確認のままとし、必要な追加証拠を識別する。 |

リポジトリのテストはスクリプトとCLIの契約を検査する。構成全体の評価には、エージェントを介したこれらのケースの適用が必要である。その評価を報告する際は、実際のエージェント・環境、ケース、判断、限界を示す。データの計算は、稼働中のサービスや、本番用測定計画の科学的な妥当性を検証するものではない。
