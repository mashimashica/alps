# Local interface

Requires Python 3.12 standard library and UTF-8 JSON. Run `python3 scripts/review.py --help` from the Skill directory for arguments. Output goes to stdout unless `--output` names a new file; an existing output is never overwritten. Exit 0 means a report was produced, even with evidence gaps. Exit 2 means an unusable envelope, parse/I/O error or output collision. Retries do not change input or business records.

Input is an object with `month` in YYYY-MM, `orders`, `events`, `coverage` arrays, and a `responsibilities` object. Each order has nonempty string `order_id`, `sku`, positive integer `ordered`, and supplied `supplier_contact`. Each event has nonempty string `event_id`, `order_id`, `sku`, valid `event_month`, and signed integer `quantity`. Booleans are not integers. Coverage has `order_id`, `sku`, `month`, and boolean `complete`. Responsibility keys are `purchasing_coordinator`, `warehouse_lead`, `data_steward`; values are recipient names/addresses. Missing recipients are reported explicitly.

Report includes all original order rows, normalized line findings, signed observed subtotal, contributing event IDs, coverage references, blockers, status, final remaining/excess quantity only when justified, and proposed actions with owner, recipients, missing responsibility keys, and draft. Diagnostics include skipped outside-month/outside-order records. Row references are zero-based array indices. Exact repeated events count once; conflicting event IDs block all potentially affected lines and contribute no quantity. Duplicate order rows remain visible and block that identity pending reconciliation. Invalid unlocatable events conservatively block all lines because their scope cannot be determined; invalid records with known scope block only that scope. An unknown current-month SKU blocks its entire known order. Invalid or missing month on a known-order event prevents excluding it and requires reconciliation. Known outside-order events do not change this review, even with other invalid fields.

Coverage requires at least one valid matching declaration, with every matching declaration true. Missing/false declarations prevent final comparison. Contradictory or invalid matching coverage also requires source reconciliation. Nonmatching coverage never removes an order line. Empty complete exports support a net of zero; missing/partial coverage permits only an observed subtotal. If no usable receipts exist under incomplete evidence, zero is only the subtotal of known valid rows, never a replacement for a missing final value.
