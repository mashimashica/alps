- `SKILL.md`: the Process Description, invocation, result interpretation, tranche boundary, continuation, and failure rules.

## Key design choices

- The agent retains request interpretation, operator communication, and result interpretation. The bundled script owns the stable validation, pagination, exact arithmetic, coverage accounting, and checkpoint mechanics.
- A completed business result requires `next_cursor: null` and `processed_records == total_records`. Incomplete invocations emit no business result file and use exit code 10 with `final: false`.
- The script never invokes the operator-only `grant-tranche` control. One invocation makes no more than the lesser of two page calls and the allowance reported by `describe`.
- The checkpoint binds the resolved API path, source-state path, output path, interval, snapshot ID, total record count, and page size. Reuse with different inputs is rejected.
- Each page is fully parsed and validated, incorporated into a copied checkpoint, and then atomically replaced. The next cursor advances only with that commit. Re-fetching an uncommitted cursor can consume another call but cannot double-count a committed page.
- An adjacent file lock serializes uses of the same checkpoint. Unique entry IDs are retained in the checkpoint to detect duplicates across pages.
- A successful page call with unusable content is reported as a consumed call and a source-contract violation. An unavailable or ambiguous page response uses exit code 21 and is not retried automatically.
- Results retain exact integer cents, include charge, credit, net, and count, sort by `vendor_id`, and retain zero and negative nets. A file output prevents a large vendor result from being lost to console truncation; small results may still be emitted directly by omitting `--output`.
- An output path must be unused for a new request. An unexpected result file beside an incomplete checkpoint is rejected so stale output cannot appear to represent partial work.
