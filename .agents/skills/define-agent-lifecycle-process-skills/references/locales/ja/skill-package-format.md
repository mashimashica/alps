# ALPS準拠Skill Packageの論理構成

この資料は、ALPS 5.7におけるSkill Packageの論理構成を示す参考例である。ALPSは、ファイル名、ファイル形式、メタデータ書式、物理的な格納構造、配布機構またはベンダー固有の登録・提示仕様を規定しない。Skillの意味と論理的整合性にはProcess FrameworkおよびALPSを適用し、表現および配備には対象環境の規則を適用する。環境固有の表現・配備情報は、正本となるSkill Descriptionから分離した「環境への対応付け」（Environment Binding）に記録できる。

## 論理構成

| 論理構成要素 | 数 | 代表的な役割 | 利用条件 |
|---|---:|---|---|
| 正本のSkill Description | 1 | SkillのName、Purpose、Outcome、発見情報および実行情報の規範上の基準 | Skill Packageごとに一つ含める。表現形式や格納場所にかかわらず、正本を一意に識別できるようにする。 |
| 参考情報およびControl | 0..* | 規格、方針、スキーマ、詳細説明その他の方向付けまたは理解支援 | 必要に応じて含めてよい。必須の参照先は、対象環境から特定し、取得できる必要がある。 |
| 実行用Enabler | 0..* | スクリプト、宣言的規則、モジュール、ツールまたはサービスとの接続 | 役割および利用条件をSkill Descriptionから識別できる必要がある。互換条件および限界は、関連する場合に示すのが望ましい。 |
| Output作成用資源 | 0..* | テンプレート、メディア、フォント、スキーマその他のOutputの作成支援 | 機能上の分類および利用条件をSkill Descriptionから識別できる必要がある。 |
| 環境への対応付け（Environment Binding） | 0..* | 対象環境の読込み、登録、能力、権限、統合または提示仕様への対応付け | 名称、配置、形式およびスキーマは対象環境が定める。正本のSkill Descriptionを再定義してはならない。 |
| 提示用資源 | 0..* | アイコン、プレビュー、表示文字列、配色その他の提示支援 | 対象環境で必要な場合に含めてよい。提示上の役割だけではALPSへの適合を実証しない。 |

資源の機能上の役割は、格納場所やファイル拡張子だけでなく、Skill実行時の機能に従って定める必要がある。同じ物理資源が複数の役割を持つ場合は、それぞれの役割と利用条件を識別できる必要がある。

## 環境への対応付けに含める代表項目

- 対象となる実行環境および適用版
- 正本のSkill Descriptionに到達できる参照
- 発見情報、実行情報、能力、権限および提示情報の対応付け
- 参照するメタデータスキーマまたは登録規則
- 必要なEnablerおよび提示用資源の参照
- 互換条件、既知の制限および再検証条件

これらの項目を一つのファイルに格納することも、複数の資源または登録情報に分けることもできる。本例では、特定の名称、ディレクトリ、記法またはシリアライズ形式を仮定しない。

## Skill Packageのレビュー基準

- Skill Packageは、正本となるSkill Descriptionを一つ含む必要がある。
- 各付随資源の機能上の役割および利用条件を、Skill Descriptionから識別できる必要がある。
- 必須の参照先は、ローカル、埋込み、レジストリまたはURIなど、宣言された対象環境の方法で特定し、取得できる必要がある。
- 環境への対応付けは、正本のSkill Descriptionの意味または規範上の強さを変更してはならない。
- Skill Descriptionと付随資源とのあいだに、不要な重複または矛盾が生じてはならない。
- Skill Packageには、Skillの理解、実行またはOutputの作成を直接支援する成果物、資源、対応付けおよび登録情報だけを含めるのが望ましい。
- Skill Packageまたは環境への対応付けを変更した場合の影響を評価し、影響を受けるSkill Description、付随資源および対応付けを識別して、必要な再検証を行うのが望ましい。
