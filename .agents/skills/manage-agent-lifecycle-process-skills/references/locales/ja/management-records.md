## 利用方法

以下のブロックは任意の補助である。適用状況とリスクによって正当化されるものを選択する。必要なブロックは汎用Process Instance Recordに含めるか、そのRecordから参照する別の管理Outputとして保持できる。記録構造および状態語彙は、適用状況に合わせて選択できる。

本管理Processの出典および基準版と、管理対象資産の出典および基準版とを別々に記録する。前者は本Process Instanceの評価に用いるOutcomeおよびTaskを定め、後者は統制対象の資産を識別する。追跡可能性が必要な場合は、到達可能な基準版への参照を用い、必要に応じて関連する記述を併記する。いずれかの基準版が変わった場合は、対応関係を再確認する。

判断、根拠、前提、証拠、影響、周知、再検証および授受は該当する範囲で記録し、使用するブロックだけを含める。不足情報は、適用状況に応じて未確認、該当なし、保留などと明示する。

管理された基準記述の意味、適用範囲または規範上の強さを変えないInstance固有の成功基準、Activity、Taskその他の詳細化は、Instantiationに該当する。これらの性質を変えるOutcome、Activity、Task、代表的なInputまたは代表的なOutputの削除、変更または追加はTailoringであり、Tailoring決定を要する。

## 記録の基礎

これらの補助を独立した管理Outputとして保持する場合に、この任意ブロックを用いる。包含するProcess Instance Recordが同じ基礎を既に示す場合は省略する。

```markdown
# 記録の基礎

- 記録の目的および現在の状態:
- 本管理Processの出典・基準版:
- 対象資産および管理対象資産の出典・基準版:
- 適用状況・範囲:
- 管理契機またはニーズ:
- 既知の制限・未解決情報:
```

## Framework宣言

| 種別 | 記述または出典 | 適用範囲 | 例外 | Tailoring可否・条件 | 根拠 |
|---|---|---|---|---|---|
| ControlまたはEnabler | | | | | |

Framework要素は、宣言された適用範囲、例外およびTailoring条件に従って適用する。情報資源は、実行時の機能に基づいてControl、Input、OutputまたはEnablerとして分類する。

## Tailoring決定

Tailoringを行う場合だけ、このブロックを用いる。

```markdown
# Tailoring決定

- 対象資産および管理対象資産の基準版:
- 適用状況・期間:
- 影響を受けるOutcome、Activity、Task、InputまたはOutput:
- 出典の記述または変更前の定義:
- Tailoring後の記述または定義:
- 変更の性質・範囲:
- リスク・要求事項・複雑性:
- 利用可能な能力・資源:
- 関連規格:
- 適用Control・Constraint:
- ステークホルダーの期待・リスク許容度:
- 評価した候補Skillまたはライフサイクルモデルと比較結果:
- 影響当事者と取得したInput:
- 事実・証拠:
- 前提・Decision Criteria:
- 決定・根拠:
- 判断状態・発効条件:
- 判断権限・承認証拠:
- 適用範囲に残るOutcome・ActivityおよびTaskに含まれる要求事項:
- 必要な厳密さ:
- Input、Outputおよび授受に対する影響:
- 監視・実績評価方法:
- 見直し条件:
- Conformance主張がある場合はその内容:
```

複数の変更を扱う場合は、ブロックを繰り返すか、各出典記述、変更後の記述、根拠および残存要件を対応付ける局所表を追加する。

未評価のTailoring済み基準版の再利用、適用状況を考慮しない一律適用、単一の測定指標・リスク・Controlの全対象に対する適用、および影響当事者の除外は、PF 7.3に示す代表的な落とし穴である。

## Decision Gate

Decision Gateが適用される場合だけ、このブロックを用いる。

```markdown
# 管理Decision Gate

- 対象および管理対象資産の基準版:
- 提案する行為:
- Gateを要求する根拠:
- Decision Criteria:
- 証拠:
- 影響・残留リスク:
- 決定および条件:
- 根拠・前提:
- 必要な周知:
- 必要な再検証:
- 保持・参照・復旧条件:
- 権限または承認の証拠:
```

Decision Gateの要否は、不可逆性、影響、適用Control・Constraintおよび実行環境に基づいて判断する。Decision Gateを用いる場合は、その適用判断、Decision Criteria、決定および条件を記録する。

永久削除は廃止とは別の管理行為として記録し、実行環境で適用される削除、権限、保持、参照および復旧に関するControlおよびConstraintに関連付ける。これらの要求はALPS自体ではなく実行環境に由来し、適用される場合は宣言した実行範囲および評価の一部となる。これらがDecision Gateを要求する場合は、Gateの条件と必要な権限の充足を記録する。

## 変更・廃止・授受

変更、廃止、または定義Processもしくは適用Processへの授受に該当する項目を用いる。

```markdown
# 変更・廃止・授受

- 対象資産および管理対象資産の基準版:
- 変更または廃止の決定:
- 影響を受けるSkill Description・付随資源:
- 依存先・利用者への影響:
- 実施済みの周知および今後必要な周知:
- 再検証の要否・結果:
- 新規発動の取扱い:
- 保持・参照・復旧の取決め:
- 受領先および授受する情報:
- 授受の意味、適用範囲、基準版および準備状態:
- 実際の結果・証拠:
- 制限・未解決リスク:
```

廃止では、新規発動の停止、依存先への影響、利用者への周知、参照のための保持および復旧を区別する。永久削除は廃止と区別して記録し、適用される実行環境のControlおよびConstraintに関連付ける。

## Conformance主張

Process Conformanceを主張しない場合、このブロックを省略する。主張する場合は、対象、適用範囲、本管理Processの基準版、Outcome、Taskまたは双方のどれを基準にするか、結論、証拠および制限を記録する。

- OutcomeへのFull Conformanceには、参照した本管理Process基準版のすべてのOutcomeを達成した証拠を要する。
- TaskへのFull Conformanceには、同じ基準版のActivityおよびTaskに含まれるすべての要求事項を充足した証拠を要する。
- 選択したFull Conformance基準を満たさない場合にTailored Conformanceを主張するには、TailoringしたProcessとその適用範囲を宣言し、その適用範囲に残されたOutcomeおよびActivity・Taskに含まれる要求事項の充足を示す。
- 個別のActivityについてのみ、独立したProcess Outcome Conformanceを主張してはならない。
- CapabilityはConformanceとは分けて評価する。
